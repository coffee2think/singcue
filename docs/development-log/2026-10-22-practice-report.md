# 2026-10-22 리포트 집계와 화면 (#28)

## 1. 배경 / 문제

- PRD F5-3은 리포트에 구간별 연습 횟수, 총 연습 시간, 날짜별 추이를 보여 주고 그 숫자가 저장된 기록을 직접 센 값과 일치하기를 요구한다. 단계 5 완료 기준은 "연습 기록이 쌓이고 리포트의 숫자가 기록과 일치한다"이다. 기술 설계 문서의 PRD 대응표는 F5-3을 "storage, 화면(집계 함수)"에 배정했다.
- 기록은 #27에서 `singcue:log`에 `PracticeRecord { videoId, sectionId, at(ISO), seconds }`로 쌓이고 `storage.loadLog()`로 읽을 수 있다. 구간 이름은 기록에 없고 영상 데이터(`singcue:video:<videoId>`)에만 있다.
- 제약: #53·#23·#29가 다른 세션에서 동시에 진행 중이라, 고칠 수 있는 파일을 새 core 집계 파일과 테스트, 새 `ReportPanel.tsx`·`ReportPanel.css`, `App.tsx`(연결만), 이 기록으로 정했다. `storage.ts`, `SettingsPanel`, `BackupPanel`, `usePracticeLog.ts`, `usePlayback.ts`, `types.ts`, `app.css`, 패키지는 고치지 않는다. 차트 라이브러리는 쓰지 않는다.

## 2. 검토한 선택지

- **삭제된 구간의 기록**
  - 지금 영상 데이터에 있는 구간만 보여 주기: 합계가 기록 수보다 작아져 "숫자가 기록과 일치"를 어긴다.
  - 기록을 `(videoId, sectionId)`로 묶고 이름은 지금 영상 데이터에서 찾되, 없으면 이름 없이(null) 따로 한 줄로 보여 주기: 합계가 항상 기록 수와 같다.
- **날짜를 묶는 기준**
  - `at`의 앞 10자(UTC 날짜): 한국 시간 오전 9시 전 기록이 전날로 묶인다.
  - 기기 시간대의 로컬 날짜: 사용자가 연습한 날과 맞는다. 테스트에서 시간대를 고정할 수 있어야 한다.
- **시간대를 테스트에서 고정하는 방법**
  - `process.env.TZ`를 테스트 안에서 바꾸기: Vitest 워커·Node 버전에 따라 반영 시점이 달라 믿기 어렵다.
  - 집계 함수가 오프셋 함수(`Date.getTimezoneOffset`과 같은 부호)를 인자로 받고 기본값은 기기 시간대로 두기: 순수 함수로 남고 테스트가 시간대별 결과를 직접 확인한다.
- **리포트가 기록을 다시 읽는 시점**
  - 렌더 중에 매번 읽기(`useMemo`로 재생 상태에 묶기): 렌더는 커밋 전이라, `usePracticeLog`가 effect 정리 함수에서 저장하는 정지 기록보다 먼저 읽는다.
  - 재생 상태를 받아 effect에서 다시 읽기: React는 한 커밋의 정리 함수를 모두 실행한 뒤 새 effect를 실행하므로 방금 저장된 기록까지 읽는다. 처음에는 effect 안에서 `setState`를 불렀는데 lint(`react-hooks/set-state-in-effect`)에 걸려, `usePracticeLog`와 같이 작은 외부 저장소 객체 + `useSyncExternalStore`로 바꾸고 effect에서는 `refresh()`만 부르게 했다.
  - 기록 저장 이벤트를 구독하기: `usePracticeLog`가 저장 알림을 내보내지 않고, 이 파일은 범위 밖이라 쓰지 않았다.

## 3. 결정 및 이유

- **집계 함수**: `src/core/practiceReport.ts`의 `buildPracticeReport(records, videos, offset?)`. 어댑터·React에 의존하지 않는다.
  - 구간별: `(videoId, sectionId)`로 묶어 횟수와 재생 시간 합. 같은 구간 ID라도 영상이 다르면 따로 센다. 정렬은 영상 ID 순, 같은 영상에서는 지금 구간 목록 순서, 지금 목록에 없는 구간은 그 뒤에 구간 ID 순.
  - **삭제된 구간**: 이름을 `null`로 두고 화면에 "삭제된 구간"(마우스를 올리면 구간 ID)으로 따로 한 줄씩 보여 준다. 영상 데이터 자체가 없는 영상의 기록도 같은 방식이다. 그래서 구간별 횟수의 합은 항상 전체 기록 수와 같다. 지금 앱에는 구간 삭제 UI가 없고, JSON 불러오기로 영상 데이터가 덮어써지면 구간이 사라질 수 있다.
  - **날짜별**: 기기 시간대의 로컬 날짜(`YYYY-MM-DD`)로 묶고, 기록이 있는 날만 오래된 날부터 둔다(빈 날을 0으로 채우지 않는다. 기록이 오래 쌓이면 줄이 너무 많아지고, 보이는 숫자가 모두 기록에서 온 값이 되게 하려고). 날짜 키는 오프셋만큼 옮긴 시각의 UTC 날짜로 계산해, 오프셋을 넘기면 기기 시간대와 상관없이 결과가 정해진다. 오프셋은 그 기록의 시각마다 물어 서머타임 전환도 따른다.
  - `at`을 날짜로 읽지 못한 기록(저장소 검증은 문자열인지만 본다)은 구간별·전체 합계에는 넣고 날짜별에서만 빼며 `undatedCount`로 따로 알린다.
  - `at`은 #27 기준으로 바퀴(재생) 시작 시각이다. 자정을 넘겨 재생한 1회는 시작한 날로 센다.
- **화면**: `ReportPanel`은 영상과 상관없이 저장된 기록 전체를 센다(로그가 전체 하나이고 PRD가 영상별 리포트를 요구하지 않음). 영상 데이터는 기록에 나오는 영상 ID만 `loadVideo`로 읽는다. 총 횟수·시간 한 줄, 구간별 표(구간·영상·횟수·시간), 날짜별 목록과 CSS 막대(그날 횟수 / 가장 많은 날 횟수)를 그린다. 시간은 기존 `formatTime`(분:초, 초 아래 버림)으로 표시하고 그 사실을 화면 안내에 적었다.
- **다시 읽는 시점**: 화면을 열 때(처음 렌더), 재생 중이 끝날 때(정지 기록이 저장된 커밋의 effect), "다시 읽기" 버튼, 다른 탭의 `singcue:log` 변경(`storage` 이벤트). 근거:
  - 연습 1회는 재생 중이 끝날 때 저장되므로 재생 종료가 가장 자연스러운 갱신 시점이다. 자동 반복의 바퀴 기록은 재생 중에 저장되는데, 재생 중에 숫자가 바뀌면 연습에 방해가 되고 `usePracticeLog`가 알림을 주지 않아, 정지할 때 함께 반영한다.
  - 같은 탭에서 JSON 불러오기(`BackupPanel`)로 기록이 바뀌는 것은 알림을 받을 수 없어(BackupPanel·SettingsPanel은 범위 밖) 버튼으로 다시 읽는다. 화면에 마지막으로 읽은 시각을 보여 준다.
- **위치**: `App.tsx`에서 `VoicePanel` 아래, `SettingsPanel` 위에 둔다. 영상을 불러오기 전에도 기록을 볼 수 있게 영상 준비 여부와 상관없이 그린다. `App.tsx`에는 import와 `<ReportPanel playbackState={playback.state} storage={storage} />` 한 줄만 추가했다.

## 6. 남은 작업 / 보류 사항

- #27의 제약대로 구절 점프로 구간 밖을 재생해도 재생 시작 때 고른 구간으로 기록되며, 리포트도 그 기록을 그대로 센다. 실제 재생 위치 기준으로 세려면 `usePlayback`·`usePracticeLog` 변경이 필요해 이번 범위에서 다루지 않았다
- 지금 앱에 구간 삭제 UI가 없어 "삭제된 구간"은 불러오기로 영상 데이터가 바뀐 경우에만 나온다. 구간 삭제·이름 변경 기능이 생기면 리포트는 다음에 다시 읽을 때 지금 이름을 따른다(기록에는 이름을 남기지 않는다)
- 같은 탭의 JSON 불러오기 직후 자동 갱신이 필요하면 `BackupPanel`의 `onImported`를 App까지 올리는 변경이 필요하다(범위 밖)
- 날짜별 추이는 기록이 있는 날만 보여 준다. 기간 필터나 빈 날 표시가 필요하면 이후에 다룬다
- 리포트의 시간 표시는 초 아래를 버리므로, 표의 구간별 시간을 더한 값과 총 시간이 1초 안쪽으로 다를 수 있다(집계 값 자체는 정확히 일치)
