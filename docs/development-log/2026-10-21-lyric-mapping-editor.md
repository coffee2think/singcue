# 2026-10-21 가사 매핑 편집 화면과 타이밍 찍기 (#17)

## 1. 배경 / 문제

- PRD F3-1: "분:초 구절" 형식으로 한 줄에 하나씩 입력하면 구절 목록이 되고, 인식된 구절 수가 표시돼야 한다. F3-2: 목록에서 구절을 고르고 재생 중 버튼을 누르면 현재 위치가 그 구절의 시작 시간으로 기록되고 목록에 바로 반영돼야 한다. 매핑(`lines`, `endT`)은 영상별로 저장되고 새로고침해도 유지돼야 한다.
- 파싱·직렬화(`src/core/lyricParser.ts`, #16), 저장(`src/adapters/storage.ts`, #2), 영상 불러오기 화면과 `playerRef`(#5, #6)는 main에 있다. 이번 작업은 이들을 잇는 상태·저장 훅과 화면이다.
- 매핑은 구간(#6)과 같은 `singcue:video:<videoId>` 키에 저장되므로, 한쪽을 저장할 때 다른 쪽을 지우면 안 된다.
- 버튼 재생·정지(#7, `usePlayback`)는 다른 세션에서 동시에 진행 중이라, `App.tsx`·`PlayerView` 변경은 최소로 하고 재생 제어 훅은 만들지 않기로 했다.

## 2. 검토한 선택지

- **입력을 목록에 반영하는 시점**
  - 입력할 때마다 파싱해 바로 저장: 버튼이 없지만, 저장하는 것은 `lines`·`endT`뿐이라 고치는 도중의 형식에 맞지 않는 줄이 새로고침하면 사라진다. 한 글자마다 저장도 일어난다.
  - "목록 만들기" 버튼으로 반영: 버튼이 하나 늘지만 고치는 도중의 텍스트가 목록을 흔들지 않는다. 인식된 구절 수는 입력하는 동안 미리 보여 줄 수 있다.
- **찍은 시간과 입력란의 관계**: 찍을 때 입력란을 매핑 텍스트로 항상 다시 쓰기 vs 입력란을 고치던 중이 아닐 때만 다시 쓰기 vs 다시 쓰지 않기. 다시 쓰지 않으면 찍은 뒤 "목록 만들기"를 누를 때 찍은 시간이 입력란의 옛 시간으로 되돌아간다. 항상 다시 쓰면 반영하지 않은 입력이 사라진다.
- **찍은 뒤 고른 항목**: 그대로 두기 vs 다음 구절로 넘기기.
- **구절 순서**: 찍은 시간이 앞 구절보다 앞서도 입력 순서를 유지하기 vs 시간순으로 다시 정렬하기.

## 3. 결정 및 이유

- "목록 만들기" 버튼으로 반영하고, 입력란 아래에 입력 중인 텍스트의 인식된 구절 수, 마지막 구절 다음 위치 여부, 구절로 세지 않은 줄 번호를 바로 보여 준다(F3-1, F3-3). 반영하면 첫 구절을 골라 바로 찍을 수 있게 한다.
- 찍을 때는 입력란이 마지막으로 반영한 매핑과 같은 텍스트일 때(고치던 중이 아닐 때)만 입력란을 새 매핑 텍스트로 바꾼다. 고치던 중이면 입력란을 그대로 둔다.
- 찍은 뒤에는 다음 구절을 고른다. 재생하면서 구절이 나올 때마다 버튼만 누르면 되도록 하기 위해서다. 마지막 구절 다음에는 "마지막 구절 다음 위치"(`endT`)를 목록 맨 아래 항목으로 두어 같은 버튼으로 찍을 수 있게 했다.
- 구절 순서는 입력 순서를 유지한다. #16에서 lyricParser가 입력 순서를 유지하기로 정했고, 순서를 바꾸면 찍던 중 고른 항목이 다른 구절로 바뀐다. 시간이 거꾸로 된 목록의 안내는 남은 작업으로 둔다.
- 위치는 구간 마킹과 같이 0.1초 단위로 맞추고, 목록에는 lyricParser의 `formatTime`(소수점 아래 표시)으로 보여 준다. 구간 패널의 `src/ui/formatTime.ts`는 초 아래를 버려 0.1초 차이를 볼 수 없다.
- 재생 중일 때만 버튼을 받는 제한은 두지 않았다. 재생 상태는 #7(`usePlayback`)이 다룰 영역이고, 정지 상태에서 찍어도 해가 없다. 현재 위치는 #6이 만든 `playerRef`에서 `getCurrentTime()`으로만 읽는다.
- 저장은 #6의 `saveSections`와 같은 방식으로, 저장 직전에 같은 영상 데이터를 다시 읽어 `lines`·`endT`만 바꾼다(`saveLyricMapping`). 두 패널이 따로 상태를 들고 있어도 서로의 데이터를 덮어쓰지 않는다. storage 어댑터는 수정하지 않았다.
- 매칭용 정규화 텍스트(`norm`)는 저장하지 않는다(#16 결정과 같음).

## 4. 구현 내용

- `src/controller/lyricMappingReducer.ts`: 상태 `{ lines, endT, draft, selected }`, 동작 `edit`, `apply`, `select`(구절 번호 또는 `'end'`), `stamp`(시간). `previewDraft()`로 입력 중 텍스트의 인식 결과를 돌려준다. 순수 함수.
- `src/controller/useLyricMapping.ts`: `useLyricMapping(videoId, storage)` 훅과 `saveLyricMapping()`. 매핑이 바뀐 동작에서만 저장하고 저장 실패(`SaveResult`)를 돌려준다.
- `src/ui/LyricMappingPanel.tsx`: 입력란, "목록 만들기", 인식된 구절 수, "지금 위치로 시작 시간 찍기", 구절 목록(`aria-pressed` 버튼)과 마지막 구절 다음 위치 항목, 저장 실패 안내.
- `src/ui/App.tsx`: 영상이 준비되면 `LyricMappingPanel`을 `SectionPanel` 아래에 연결. 같은 부모 안에서 `SectionPanel`의 `key={videoId}`와 겹치지 않도록 `key={`lyrics:${videoId}`}`를 쓴다(처음에 같은 key를 써 React 중복 key 경고가 났다).
- `src/ui/app.css`: 패널 스타일.

## 6. 남은 작업 / 보류 사항

- 찍은 시간이 앞 구절보다 앞서거나 뒤 구절보다 늦어 시간 순서가 어긋나도 안내하지 않는다. 구절 점프(PRD 4단계)가 다음 구절 시간을 쓰므로 어긋난 목록을 안내할지, 정렬할지 정해야 한다.
- 구절 하나만 고치거나 지우는 편집은 입력란을 고쳐 "목록 만들기"로 다시 반영하는 방식뿐이다. "목록 만들기"는 찍은 시간을 포함해 목록 전체를 입력란 내용으로 바꾼다.
- 재생 중일 때만 찍기 버튼을 받도록 제한하는 일은 재생 상태를 다루는 #7(`usePlayback`)이 병합된 뒤 필요하면 연결한다.
- 매핑 JSON 내보내기·불러오기(F3-4)는 별도 이슈 범위다.

## 7. main 반영과 충돌 해결 (#43 병합 후)

- 버튼 재생·정지(#43, `usePlayback`)가 main에 병합돼 `src/ui/App.tsx`가 충돌했다. `origin/main`(`a068042`)을 merge commit으로 반영했다(force push 없음).
- 해결: main의 `PlaybackControls`·`usePlayback` 연결을 그대로 두고, `LyricMappingPanel`은 main이 `PlaybackControls`·`SectionPanel`을 묶은 fragment 안 `SectionPanel` 바로 뒤로 옮겼다. 같은 부모 안이라 `key={`lyrics:${videoId}`}`는 그대로 둔다. `app.css`는 자동 병합됐고, main 대비 차이는 이번에 추가한 패널 스타일뿐인 것을 확인했다.
- `usePlayback`과의 관계: `usePlayback`은 재생 상태(`state`)와 `play`·`stop`만 내주고 현재 위치는 내주지 않는다. main의 `SectionPanel`도 여전히 `playerRef.current.getCurrentTime()`으로 위치를 읽으므로, 타이밍 찍기도 같은 방식을 유지했다. 재생 상태로 찍기 버튼을 제한하는 일은 이번에도 하지 않았다(6절 보류 사항 그대로). 코드 정리는 필요 없었다.
