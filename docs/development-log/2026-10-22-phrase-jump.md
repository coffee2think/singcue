# 2026-10-22 구절 인식 점프 연결과 결과 안내 (#22)

## 1. 배경 / 문제

- PRD F4-1~F4-3, F4-5: 정지 상태에서 구절을 말하면 가장 비슷한 구절을 찾아, 유사도가 기준 이상이면 그 다음 구절 시작에서 프리롤만큼 앞부터 재생한다. 기준 미만이면 이동하지 않고 가장 가까운 구절과 점수를 보여 주며 다시 말하도록 안내한다. 마지막 구절이면 "마지막 구절 다음 위치"(`endT`)가 있을 때 그곳으로, 없으면 이동하지 않고 이유를 안내한다. 재생 중에는 구절로 이동하지 않는다.
- 선행 작업은 모두 main에 있다: `matchPhrase`(#21, PR #50), 음성 제어 `useVoice`·`VoicePanel`(#11, PR #45), 가사 매핑 편집(#17, PR #44), 반복 구절 선택 결정(#20, PR #48). #11까지는 `decide`가 `phrase`로 판별해도 "구절 인식 점프는 아직 지원하지 않습니다"만 기록했다.
- #21 기록의 후속 항목: `phrase` 결과를 `matchPhrase`에 넘기고, 플레이어 현재 위치를 `hint`로, `seekTo`에 `prerollStart`를 적용해 재생하는 연결이 남아 있었다.
- 같은 시기에 #27 세션이 `storage.ts`, `usePracticeLog.ts`, `SettingsPanel.tsx`, `settingsForm.ts`를 고친다. 이 작업은 `App.tsx`, `usePlayback.ts`, `playback.ts`, `useVoice.ts`, `VoicePanel.tsx`, `VoicePanel.css`, 각각의 테스트, 이 기록만 고치기로 범위를 정했다. `usePlayback`의 기존 공개 형태(`state`, `play`, `stop`, `subscribeLap` 등)는 #27이 그대로 쓰므로 바꾸지 않고 더하기만 한다.

## 2. 검토한 선택지

- **임의 위치 재생을 어디에 둘지**
  - `useVoice`에서 플레이어를 직접 `seekTo`·`play`: `useVoice`가 플레이어 ref와 프리롤 설정을 따로 알아야 하고, 구간 끝 확인의 직전 위치(`watch.lastTime`)를 비울 수 없다.
  - `usePlayback`에 `playAt(time)`을 더하고 순수 로직은 `playback.ts`의 `playFrom`으로: `play`(구간 재생)와 같은 경로로 프리롤을 읽고 구간 끝 확인 상태를 정리할 수 있다.
- **이동 위치를 어떻게 정할지**: `matchPhrase`의 `seekTo`는 프리롤을 빼기 전 위치다(#21). 호출 측에서 `prerollStart(seekTo, preroll)`을 적용한다.
- **구간 끝 동작과의 관계**: 점프 뒤 재생 중에도 마지막으로 `play`에 넘긴 구간의 끝 확인을 그대로 둘지, 점프하면 끌지. 영상 화면을 직접 눌러 재생할 때도 그 구간의 끝을 확인하는 기존 동작(#13)과 맞추는 쪽을 골랐다.
- **결과 안내 위치**: 판별 기록 항목에만 붙이기와, 최근 구절 결과를 따로 크게 보이기. 기록은 위에 쌓이지만 "다시 말해 주세요" 안내가 다른 항목과 섞이면 놓치기 쉬워 둘 다 하기로 했다.

## 3. 결정 및 이유

- `usePlayback`에 `playAt(time): number | null`을 더했다. 플레이어가 준비됐으면(`canPlayAt`: 준비 전이 아님) 구간을 고르지 않아도 재생한다. 프리롤은 `play`와 같이 쓸 때마다 `singcue:settings`에서 읽는다. 위치를 옮기므로 구간 끝 확인의 직전 위치를 비워, 옮기기 전 위치와 비교해 구간 끝을 지났다고 보지 않게 했다. 옮긴 위치를 돌려줘 화면에 실제 재생 위치를 보일 수 있게 했다.
- 구간 끝 확인은 마지막으로 `play`에 넘긴 구간을 그대로 쓴다(영상 화면 직접 재생과 같은 규칙). 구절로 점프한 뒤 그 구간의 끝을 지나면 설정의 구간 끝 동작이 적용된다.
- 상태 게이트는 `decide`의 기존 규칙(정지 상태에서만 `phrase`, 재생 중에는 `state`로 무시)을 그대로 쓰고 따로 만들지 않았다. 구절은 최종 결과에서만 판별된다(`judgeResult`는 중간 결과에서 정지만 받음).
- `useVoice`는 `phrase` 판별마다 `storage.loadVideo(videoId)`로 가사 매핑(`lines`, `endT`)을, `loadSettings()`로 유사도 기준(`similarityThreshold`)을 읽는다. 가사 매핑 화면이나 설정에서 바꾼 값이 다음 인식부터 반영된다(F4-4의 "다음 인식부터 적용"). `hint`는 #20 결정대로 매칭 시점의 플레이어 `getCurrentTime()`이다.
- 매칭 결과를 이동 여부로 나누는 순수 함수 `resolvePhrase`를 두어 Vitest로 확인할 수 있게 했다. 결과는 `jump`(이동), `below`(기준 미만), `no-next`(마지막 구절, `endT` 없음), `no-lines`(가사 매핑 없음) 네 가지다.
- 이동했을 때만 명령으로 센다(중복 방지 시각과 발화 처리 기록을 갱신하고, 시작 명령과 같은 자동재생 차단 감시를 건다). 이동하지 못한 구절은 0.8초 중복 방지에 걸리지 않고 바로 다시 말할 수 있다.
- 구절 결과에는 반응 시간을 재지 않았다. 반응 시간 기록·표는 #12의 정지·시작 명령 기준이라 바꾸지 않았다.

**앱 내 브라우저 확인(가짜 인식)**

아래 항목은 모두 **실제 마이크·음성이 아니라** 페이지에 가짜 `getUserMedia`(오실레이터 스트림)와 가짜 `SpeechRecognition`(스크립트로 최종 결과를 넣음)을 넣어 확인했다. 플레이어(YouTube IFrame, 영상 `dQw4w9WgXcQ`)와 앱 코드는 실제 것이다. 가사 매핑은 저장소에 가상의 구절 5개(0:10, 0:20, 0:30, 0:40, 0:50. 3번째와 5번째가 같은 문장)와 `endT` 1:00을 넣었다. 재생 위치는 정지 뒤 구간 패널의 "여기부터"로 읽었다(초 아래 버림).

- 기준 이상 이동: 정지(0:00)에서 "파란 우산을 펼쳐 들고" → "재생 중", 결과 "1번째 구절 … 유사도 1.00 / 기준 0.50 → 0:20의 프리롤 앞 0:18.5부터 재생". 정지(0:27)에서 "골목 끝까지 걸어가요" → 약 1.5초 뒤 정지 버튼, 위치 0:29(0:28.5에서 재생됨)
- 반복 구절 힌트(#20): 위치 0:29에서 같은 문장 → 3번째 구절로 골라 0:38.5부터 재생(위치 0:39). 위치 0:51에서 같은 문장 → 5번째(마지막) 구절로 골라 `endT` 1:00의 프리롤 앞 0:58.5부터 재생(위치 0:59). 마지막 구절의 `endT` 이동도 이것으로 확인했다
- 기준 미만: 위치 0:59에서 "하늘 높이 날아가는 연" → 이동하지 않음(상태 "정지", 위치 0:59 그대로). "가장 가까운 구절: 5번째(마지막) 구절 … 유사도 0.10 / 기준 0.50", "유사도가 기준(0.50)보다 낮아 이동하지 않았습니다. 구절을 다시 말해 주세요"가 `role="alert"` 상자로 보임
- 유사도 기준 반영: 기준 0.5에서 "파란 우산을 펴고 들고"(유사도 0.78) → 이동. 저장소의 `similarityThreshold`를 0.9로 바꾼 뒤 같은 말 → 이동하지 않음, "기준 0.90" 표시. 설정 화면에는 유사도 기준 입력이 없어 저장소에 직접 넣었다
- 마지막 구절, `endT` 없음: `endT`를 지운 뒤 위치 0:50에서 마지막 구절 문장 → 이동하지 않음, "마지막 구절이지만 "마지막 구절 다음 위치"가 없어 이동하지 않았습니다…" 안내
- 가사 매핑 없음: `lines`를 비운 뒤 구절 → 이동하지 않음, "이 영상에 가사 매핑이 없어…" 안내
- 재생 중 무시: 점프 뒤 재생 중에 "종이배를 띄워 보내요" → "무시 · 재생 중 상태에서는 받지 않는 명령입니다", 이동 없음. 이어서 "멈춰" → 정지
- 단계 4 완료 기준(정지 상태에서 구절을 말하면 그 다음 구절 위치에서 재생): 가짜 인식으로는 위 항목들로 확인했다

## 6. 남은 작업 / 보류 사항
