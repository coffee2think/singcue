# 2026-10-22 구간 끝 동작 (#13)

## 1. 배경 / 문제

- PRD F2-8: 구간 끝 도달 후 1초 이내에 설정대로 동작한다. 자동 정지(기본)는 정지 상태, 자동 반복은 구간 시작으로 돌아가 정지 명령 전까지 반복, 계속 재생은 구간과 상관없이 이어서 재생한다.
- 기술 설계 문서 "구간 끝 감지": 유튜브 플레이어에는 구간 끝 이벤트가 없어 재생 중에만 0.25초마다 현재 위치를 확인한다. 구간 끝 동작 표는 자동 정지 = 재생 중 → 정지, 자동 반복 = 재생 중을 유지하고 구간 시작으로, 계속 재생 = 아무 동작 없음.
- #7(버튼 재생·정지)까지는 재생 버튼으로 시작해도 구간 끝을 지나 계속 재생됐다. 설정 패널(#14)은 `endAction`을 저장만 하고 아무도 읽지 않았다.
- #24 결정(`2026-10-22-auto-repeat-preroll-count.md`): 자동 반복은 매 바퀴 `prerollStart(section.start, preroll)`로 이동해 재생 중을 유지하고 프리롤은 바퀴마다 설정에서 읽는다. 구간 끝에 도달해 시작으로 돌아갈 때마다 "바퀴 완료"를 `practiceCounter`(#26)가 받을 수 있게 내보낸다. 이슈 인수 조건의 "임시 동작을 코드 주석과 개발 기록에 명시"는 이 결정으로 대체됐으므로 임시 동작을 두지 않고 결정을 그대로 따랐다.
- 제약: #12·#21·#26이 다른 세션에서 동시에 진행 중이라 고칠 수 있는 파일이 `usePlayback.ts`, `playback.ts`, `playbackMachine.ts`와 그 테스트로 정해졌다. `App.tsx`, `useVoice.ts`, `types.ts`는 고치지 않는다. 연습 기록 저장은 #27 범위다.

## 2. 검토한 선택지

- **어느 구간의 끝을 볼지**
  - `App`의 고른 구간을 `usePlayback`에 넘기기: 구간을 고르기만 하고 재생하지 않은 경우까지 정확하지만 `App.tsx`를 고쳐야 한다(범위 밖).
  - 마지막으로 `play(section)`에 넘긴 구간을 훅이 기억하기: `App`을 고치지 않는다. 버튼과 음성 시작 명령이 모두 `play(section)`을 거치므로 연습 중인 구간과 같다.
- **끝 도달 판정**
  - 현재 위치 ≥ 끝: 단순하지만, 자동 정지 뒤 영상 화면을 눌러 이어서 재생하거나 구간 끝 뒤에서 직접 재생하면 0.25초마다 다시 멈춰 구간 뒤를 들을 수 없다.
  - 직전 확인 위치 < 끝 ≤ 현재 위치(끝을 "지나는 순간"만): 위 문제가 없다. 위치를 옮긴 직후에는 직전 위치를 버려 이동 자체를 지난 것으로 보지 않게 해야 한다.
- **바퀴 완료를 바깥에 여는 방식**
  - `usePlayback`의 옵션 콜백(`onLapComplete`): 간단하지만 받는 쪽(#27의 연습 기록 훅)이 `playback.state`도 필요해 `usePlayback`보다 뒤에 호출돼야 하므로, 콜백을 앞에서 넘기려면 ref로 우회해야 한다.
  - 돌려주는 값에 구독 함수(`subscribeLap(listener) => unsubscribe`): 훅 호출 순서와 상관없이 뒤에서 `useEffect`로 연결할 수 있다. `App`을 고치지 않아도 기존 동작에 영향이 없다.

## 3. 결정 및 이유

- 끝 확인 대상은 마지막으로 `play`에 넘긴 구간이다. 영상 화면을 직접 눌러 재생해도 이 구간의 끝을 본다. 새 영상을 불러오면(`unload`) 비운다.
- 끝 판정은 "지나는 순간"으로 한다(`crossedSectionEnd`). 재생 중이 될 때, 재생 버튼으로 다시 재생할 때, 자동 반복으로 이동한 직후에는 직전 위치를 비운다.
- 확인은 상태가 '재생 중'인 동안만 `setInterval(250ms)`로 돈다. 정지·준비 전이 되면 효과 정리로 멈춘다.
- 구간 끝 동작과 프리롤은 끝을 지났을 때만 `storage.loadSettings()`로 읽는다. 매 0.25초 저장소를 읽지 않으면서도, 반복 중에 바꾼 값이 다음 구간 끝부터 반영된다. `storage.ts`는 읽기만 했다.
- 자동 정지는 `pause()`만 한다. 확인 간격 때문에 끝보다 최대 약 0.25초 뒤에서 멈출 수 있지만, 끝 위치로 다시 `seekTo`하면 정지 중 이동이 버퍼링(재생 중으로 봄) 이벤트를 만들 수 있어 넣지 않았다. 설계 문서의 "끝 위치에서 멈춘다"와는 이 정도 차이가 있다.
- 자동 반복은 #24 결정대로 `playSection(player, section, preroll)`로 이동·재생한다. 재생 중을 유지하므로 상태 머신(`playbackMachine.ts`)은 바꿀 필요가 없었다.
- 바퀴 완료는 `subscribeLap`으로 연다. 형태는 다음과 같다.

  ```ts
  type LapComplete = {
    section: Section;
    /** 바퀴를 재생하기 시작한 시각. Date.now() 기준 ms */
    startedAt: number;
    /** 바퀴의 재생 시간(초). 프리롤 구간도 포함 */
    seconds: number;
  };
  subscribeLap: (listener: (lap: LapComplete) => void) => () => void;
  ```

  - 단위는 위임받은 권고(시각은 `Date.now()` ms, 재생 시간은 초)를 따랐다. `PracticeRecord.seconds`가 초 단위라 #27에서 바로 쓸 수 있다.
  - 바퀴 시작 시각은 상태가 재생 중이 된 시각(첫 바퀴)과 직전 바퀴가 끝난 시각(이후 바퀴)이다. 재생 시간은 벽시계 차이라 이동 직후 버퍼링 시간(실측 약 0.27초)도 들어간다.
  - 바퀴 완료는 자동 반복에서 구간 끝을 지나 시작으로 돌아갈 때만 보낸다. 자동 정지나 정지 명령으로 멈춘 마지막 바퀴는 #24 결정대로 `practiceCounter`가 재생 중 → 정지 전이로 처리한다(이 경우 마지막 바퀴의 시작 시각은 직전 바퀴 완료의 `startedAt + seconds`다).
  - 재생 중에 재생 버튼을 다시 누르면 위치만 처음으로 돌아가고 바퀴 시작 시각은 그대로 둔다. 재생이 끊기지 않았으므로 그 시간도 연습 시간에 넣는 편이 맞다고 봤다.

**확인 중 발견한 문제 (이번 범위에서 고치지 않음)**

- 자동 반복으로 이동한 직후 약 0.3초 안(이동 뒤 버퍼링 중)에 정지 버튼을 누르자, 플레이어가 버퍼링(3) 상태에 머문 채 위치만 20.15초에 멈췄고 일시정지(2) 이벤트를 보내지 않았다. 앱은 계속 "재생 중"으로 보였고 정지 버튼을 다시 눌러도 이벤트가 오지 않았다. `playVideo`를 보내면 바로 재생(1)으로 돌아왔다.
- iframe 명령으로 따로 재현해 보니 `seekTo` 뒤 `playVideo`를 함께 보낸 경우와 `seekTo`만 보낸 경우 모두 버퍼링 중 `pauseVideo`가 같은 결과였다. 버퍼링이 먼저 끝난 경우에는 정상적으로 일시정지(2)가 왔다. 즉 자동 반복의 `play()` 호출 때문이 아니라 "이동 직후 버퍼링 중 일시정지"라는 YouTube 쪽 동작이고, #7의 재생 버튼 직후 정지에도 같은 일이 생길 수 있다. 자동 반복은 바퀴마다 이동하므로 바퀴 경계에서 정지하면 더 자주 만날 수 있다.
- 이때 음성 시작 명령은 상태가 재생 중이라 무시되므로, 사용자는 재생 버튼이나 영상 화면으로 풀어야 한다. 고치려면 어댑터(`playerAdapter`)가 버퍼링 중 일시정지를 알리거나 상태 판단 규칙을 바꿔야 해 이번 파일 범위 밖이다.
- 창이 hidden인 상태에서 본 결과라 화면에 보이는 창에서도 같은지는 확인하지 않았다.

**미확인**

- 실제 음성 시작 명령으로 자동 반복을 돌렸을 때 자동재생 차단 안내가 뜨지 않는지(위 (b)는 코드와 상태 기록으로만 판단)
- 화면에 보이는(foreground) 창, Chrome 정식 브라우저, 다른 브라우저, 실제 모바일 기기
- `usePlayback` 훅 자체의 자동 테스트: 화면 테스트 환경이 없어(#7과 같음) 로직을 `playback.ts`의 순수 함수로 빼서 테스트하고 훅은 브라우저에서 확인했다
- 영상 끝과 구간 끝이 거의 같은 경우(끝 확인 전에 영상이 끝남): 테스트·브라우저 모두 보지 않았다. 이때는 끝남(ended) 이벤트로 정지가 되어 자동 반복도 멈출 것으로 예상한다
- 바퀴 완료를 화면에서 쓰는 곳은 아직 없다. `App.tsx`가 범위 밖이라 연결하지 않았고, 연결은 #27에서 한다

## 6. 남은 작업 / 보류 사항

- 이동 직후 버퍼링 중 정지가 무시되는 문제(위 "발견한 문제")의 처리 방식을 따로 정해야 한다. 예: 어댑터가 `pause()` 뒤 상태 변화가 없으면 정지를 알리기, 또는 재생 위치가 멈춘 것을 정지로 보기.
- 끝 확인 대상이 "마지막으로 재생한 구간"이라, 재생 중에 다른 구간을 고르기만 하면 재생 버튼을 다시 누를 때까지 이전 구간의 끝을 본다. 고른 구간을 바로 따르게 하려면 `App.tsx`에서 고른 구간을 넘겨야 한다.
- #27에서 `subscribeLap`을 `practiceCounter`(#26)의 바퀴 완료 입력으로 연결한다.
- 기술 설계 문서의 구간 끝 동작 표(자동 반복 "미확정")와 "끝 위치에서 멈춘다"는 문구는 이번에 고치지 않았다.
