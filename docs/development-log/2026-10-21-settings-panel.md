# 2026-10-21 설정 패널: 프리롤·구간 끝 동작·명령어 편집 (#14)

## 1. 배경 / 문제

- PRD F2-7(프리롤), F2-9(명령어 편집)와 "설정 항목" 표의 단계 2 항목(구간 끝 동작, 프리롤, 정지·시작 명령어, 정지 즉시 실행, 짧은 발화 허용 글자 수)을 사용자가 바꿀 수 있어야 한다.
- 저장은 storage 어댑터(#2)의 `singcue:settings`가 이미 맡고 있고, 기본값은 `src/core/defaultSettings.ts`(`DEFAULT_SETTINGS`)에 있다. 이번 작업은 그 위에 화면과 입력값 확인을 얹는 것이다.
- 인수 조건: 4개 값 변경, 명령어 목록 편집과 새로고침 후 유지, 기본 목록을 줄이지 않고 제공·기본값으로 되돌리기, 프리롤 0 이상·짧은 발화 허용 글자 수 0 이상의 정수만 받기.

## 2. 검토한 선택지

- **저장 시점**: 값을 바꿀 때마다 바로 저장하기와, "저장" 버튼으로 한꺼번에 저장하기. 바로 저장하면 숫자를 지우고 다시 쓰는 중간 상태(빈 값, "1.")나 명령어 목록을 고치는 중간 상태가 그대로 저장되거나, 틀린 값일 때 무엇이 저장됐는지 알기 어렵다.
- **입력값 확인 위치**: storage 어댑터의 `toSettings`에서 범위까지 확인하기와, 화면 쪽 순수 함수에서 확인하기. 어댑터는 #6(구간 마킹) 세션도 함께 건드릴 수 있어 이번에는 수정하지 않기로 했다.
- **명령어 목록 입력 방식**: 항목마다 입력란과 추가·삭제 버튼을 두기와, 한 줄에 하나씩 쓰는 textarea. textarea가 구현이 단순하고 여러 개를 한 번에 붙여 넣기 쉽다.

## 3. 결정 및 이유

- "저장" 버튼으로 저장한다. 저장할 때 모든 항목을 확인하고, 하나라도 틀리면 항목 아래에 안내만 보여 주고 아무것도 저장하지 않는다.
- 입력값 확인은 `src/ui/settingsForm.ts`의 순수 함수로 두었다. 기술 설계 문서가 화면 테스트를 범위 밖으로 정했으므로, 확인 규칙을 Vitest로 검증할 수 있게 하려는 것이다. storage 어댑터는 수정하지 않았다.
- 숫자 입력은 `type="number"` 대신 글자 입력란과 정규식으로 확인한다. 브라우저의 number 입력은 "1e2", "-0" 같은 값을 받거나 틀린 값을 빈 문자열로 바꿔 버려, 무엇이 틀렸는지 안내하기 어렵다.
  - 프리롤: 0 이상의 숫자(소수 허용, "1.5", ".5"). 음수, 지수 표기, 단위가 붙은 값("1.5초"), 무한대가 되는 값은 받지 않는다.
  - 짧은 발화 허용 글자 수: 0 이상의 정수. "2.0", "1e2"도 받지 않는다.
- 명령어 목록은 줄바꿈이나 쉼표로 나누고, 앞뒤 공백·빈 항목·정규화하면 빈 글자가 되는 항목("!!")·정규화하면 같은 중복("Stop"과 "stop")을 뺀다. 정규화는 commandMatcher와 같은 `normalize`를 쓴다.
- 정지·시작 목록이 비면 음성으로 정지·시작할 수 없게 되므로 저장을 막는다.
- 정지 명령어가 들어 있는 시작 명령어(예: 정지 "정지"와 시작 "정지해제")는 저장을 막는다. commandMatcher의 `decide`는 발화에 정지 명령어가 있으면 정지로 판별하므로 그런 시작 명령어로는 시작할 수 없다. 기본 목록에는 이런 겹침이 없음을 테스트로 확인했다.
- "기본값으로 되돌리기"는 패널의 6개 항목을 `DEFAULT_SETTINGS`로 바꾸고 바로 저장한다. 패널에 없는 유사도 기준·최소 재생 시간(단계 4, 5)은 저장된 값을 그대로 둔다. 기본 명령어 목록은 `DEFAULT_SETTINGS`를 그대로 써서 줄이지 않는다.
- 저장 실패(저장 공간 부족, 저장소 접근 불가)는 storage 어댑터의 `SaveResult.reason`에 맞춰 안내하고, 이전 설정을 유지한다.
- App.tsx는 `<SettingsPanel />`를 영상 영역 아래에 붙이는 두 줄만 고쳤다. 패널은 저장소를 직접 만들어 쓰고(`storage` prop으로 바꿀 수 있음), 저장에 성공하면 `onChange`로 알린다. 컨트롤러가 생기면 App에서 설정 상태를 받아 넘기도록 연결할 수 있다.

## 4. 구현 내용

`src/ui/`

- `settingsForm.ts`: `toDraft`, `defaultDraft`, `parsePreroll`, `parseShortRuleChars`, `parseWordList`, `overlappingWords`, `readDraft`. 입력란 문자열(`SettingsDraft`)과 설정(`PanelSettings`, `Settings`에서 패널 6개 항목) 사이를 바꾸고 항목별 오류 문구를 정한다.

**자동 검증**

- `npm test`: 테스트 파일 17개, 테스트 262개 통과(이번에 추가한 `settingsForm.test.ts` 43개)

**실제 브라우저 확인** (앱 내 브라우저, Chromium 계열, `npm run dev`로 띄운 `http://localhost`. 확인 전 `singcue:settings`를 지우고 시작)

- 처음 열면 기본값이 표시된다: 자동 정지, 1.5, 2, 정지 즉시 실행 꺼짐, 정지 명령어 6개, 시작 명령어 4개(기본 목록 전체)
- 프리롤 `-1`, 짧은 발화 `1.5`로 저장 → 두 항목 아래에 각각 안내가 뜨고 `singcue:settings`는 쓰이지 않았다(null 유지).
- 자동 반복, 프리롤 0.5, 짧은 발화 3, 정지 즉시 실행 켬, 정지 명령어에 "그만", 시작 명령어에 "가자" 추가 후 저장 → "설정을 저장했습니다." 안내, `singcue:settings`에 그대로 저장(유사도 기준 0.5, 최소 재생 시간 3은 유지)
- 새로고침 → 입력란에 저장한 값이 모두 그대로 표시된다.
- 정지 명령어를 모두 지우고 저장 → "정지 명령어를 하나 이상 입력하세요." 안내, 저장 안 됨
- 정지 "정지", 시작에 "정지해제" 추가 후 저장 → 겹침 안내, 저장 안 됨
- "기본값으로 되돌리기" → "기본값으로 되돌려 저장했습니다." 안내, 저장값이 `DEFAULT_SETTINGS`와 같아지고 새로고침 뒤에도 기본값 표시
- 375px 폭에서 가로 스크롤 없음, 콘솔 오류 없음

**미확인**

- 저장 공간 부족·저장소 접근 불가 때의 화면 안내: 실제로 일으켜 보지 않았다. 어댑터의 `SaveResult` 테스트(#2)로만 확인했다.
- Chrome 정식 브라우저, 다른 브라우저, 실제 모바일 기기
- 키보드만으로 조작하는 흐름과 화면 낭독기 안내

**아직 동작에 연결되지 않은 설정** (화면에서 바꾸고 저장되는 것까지만 확인)

- 재생·인식을 이어 줄 컨트롤러(`src/controller`)가 아직 main에 없어, 저장한 설정이 실제 재생과 인식에 쓰이지 않는다.
  - 프리롤, 구간 끝 동작: playbackMachine·컨트롤러 연결 전
  - 정지·시작 명령어, 짧은 발화 허용 글자 수: `commandMatcher.decide`가 `Settings`를 받도록 되어 있지만 화면의 음성 인식과 연결되지 않았다.
  - 정지 즉시 실행: speechAdapter의 중간 결과를 쓰는 경로가 연결되지 않았다. 기본값도 PRD에서 미정(#15에서 측정 후 결정)이다.

## 6. 남은 작업 / 보류 사항

- 컨트롤러가 생기면 App이 설정을 상태로 들고 `SettingsPanel`의 `onChange`로 갱신해 컨트롤러에 넘긴다.
- storage 어댑터의 `toSettings`는 형식(숫자인지)만 확인하고 범위(프리롤 0 이상, 정수)는 확인하지 않는다. 저장소를 직접 고친 경우 음수 프리롤 등이 읽힐 수 있다. 화면에서는 그런 값으로 다시 저장할 수 없지만, 읽을 때도 범위를 확인할지는 storage 쪽 작업에서 정한다.
- 유사도 기준(단계 4), 연습 1회 최소 재생 시간(단계 5)은 해당 단계에서 패널에 추가한다.
- 저장하지 않은 변경이 있을 때 표시하거나 화면을 떠날 때 경고하는 기능은 넣지 않았다.
