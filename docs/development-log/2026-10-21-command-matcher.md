# 2026-10-21 음성 명령 판별 decide()와 공용 normalize (#8)

## 1. 배경 / 문제

- 음성 인식 결과를 정지·시작·구절 점프·무시 중 무엇으로 처리할지 정하는 규칙(PRD F2-2~F2-5)이 필요하다. 기술 설계 문서는 이 판별을 순수 함수 `decide(candidates, state, settings, lastCommandAt)`로 두고, 컨트롤러는 그 결과만 따르도록 정했다.
- PoC 로그에서 가사 문장이 시작 명령으로 두 번 오인식됐다("…시작을 하다 보면", "시작이고…"). 짧은 발화 규칙으로 이를 막고 회귀 테스트로 고정해야 했다.
- 구절 매칭(phraseMatcher)도 같은 정규화를 쓰므로 `normalize`를 공용 모듈로 분리했다.
- 상태 타입은 #4에서 병합된 `PlaybackState`('unready' | 'stopped' | 'playing'), 결과 타입은 #1의 `types.ts`에 있던 `Decision`을 그대로 썼다.

## 2. 검토한 선택지

- **판별 시각을 얻는 방법**: 이슈의 시그니처는 인자가 4개라 중복 방지(0.8초)에 필요한 현재 시각이 없다.
  - 함수 안에서 `performance.now()`·`Date.now()` 호출: 시그니처는 그대로지만 순수 함수가 아니게 되고 테스트에서 시간을 고정하기 어렵다.
  - 5번째 인자 `now`를 받기: 순수 함수를 유지하고, 시계 선택(`performance.now()` 등)을 컨트롤러에 맡긴다.
- **명령어가 섞였지만 짧은 발화 규칙에 걸린 문장(정지 상태)**: 구절 점프 후보로 넘기기 vs `ignore`(`short-rule`)로 끝내기.
- **나머지 글자를 셀 때 빼는 명령어**: 찾은 명령어 하나만 빼기 vs 정지·시작 명령어를 모두 빼기.
- **정규화 범위**: PoC의 `norm`처럼 지울 기호를 목록으로 적기 vs 문자·숫자가 아닌 모든 글자를 지우기.

## 3. 결정 및 이유

- `decide(candidates, state, settings, lastCommandAt, now)`로 `now`를 5번째 인자로 추가했다. 이슈가 요구하는 "순수 함수"를 지키려면 시각을 밖에서 받아야 한다. 앞의 4개 인자는 이슈 정의와 같다. `lastCommandAt`은 직전 명령이 없으면 `null`이다.
- 판별 순서는 설계 문서의 4단계(명령어 포함 → 짧은 발화 → 상태 → 중복)를 따른다. 그래서 여러 이유에 동시에 걸리면 앞 단계의 이유를 돌려준다(예: 재생 중 0.8초 안의 "시작"은 `debounce`가 아니라 `state`).
- 정지 우선: 후보 하나라도 정지 조건을 만족하면 시작 조건을 만족하는 후보가 있어도 정지로 판별한다. 정지 상태에서는 그 결과 `state`로 무시된다. PoC의 `matchCmd`도 정지를 먼저 확인하고 상태 게이트에서 무시했으므로 같은 동작이다.
- 명령어가 섞였지만 나머지가 기준을 넘는 문장은 정지 상태에서도 구절로 넘기지 않고 `short-rule`로 끝낸다. 이슈 인수 조건이 `ignore`(`short-rule`)를 명시했고, PRD F2-4가 "명령어가 섞인 가사 문장은 재생 중이든 아니든 실행되지 않는다"고 정했기 때문이다.
- 나머지 글자는 정지·시작 명령어를 모두 지운 뒤 센다. "잠깐 멈춰"나 "시작 멈춰"처럼 명령어 두 개를 붙여 말한 경우를 짧은 발화로 보기 위해서다. 긴 명령어부터 지워 부분 겹침 영향을 줄였다.
- 후보는 앞에서부터 5개만 본다(PRD F4-1의 "최대 5개"). 정규화 후 빈 후보는 버리고, 남는 후보가 없으면 `no-match`다. 구절(`phrase`)로 넘길 때는 phraseMatcher가 자체적으로 정규화하도록 원문 후보를 넘긴다.
- 설정의 명령어도 같은 `normalize`로 정규화해 비교한다. 사용자가 "Stop "처럼 입력해도 맞도록 하기 위해서다.
- 중복 방지 창(800ms)은 PRD에 고정값으로 있고 설정 항목이 아니라서 상수 `DEBOUNCE_MS`로 두었다. 경계는 PoC와 같이 `now - lastCommandAt < 800`이면 무시, 800ms 이상이면 통과다. 구절 점프도 실행되는 명령으로 보고 중복 방지를 적용했다.
- `normalize`는 소문자로 바꾸고 유니코드 문자(`\p{L}`)·숫자(`\p{N}`)가 아닌 모든 글자를 지운다. 설계 문서의 "공백과 기호를 지운다"를 그대로 옮긴 것으로, PoC의 기호 목록에 없던 기호(괄호, 콜론 등)도 지워진다.
- 정지 즉시 실행(F2-6, 중간 결과·같은 발화 1회 실행)은 speechAdapter·컨트롤러가 언제 `decide`를 부를지의 문제라 이번 범위에 넣지 않았다. `decide`는 `stopOnInterim` 설정을 보지 않는다.

## 4. 구현 내용

- `src/core/normalize.ts`: `normalize(text)`
- `src/core/commandMatcher.ts`: `decide(...)`, 상수 `MAX_CANDIDATES`(5), `DEBOUNCE_MS`(800)
- `src/core/normalize.test.ts`: 소문자화, 공백·기호 제거, 빈 결과
- `src/core/commandMatcher.test.ts`
  - 기본 정지·시작 명령어 전부, 대소문자·기호 무시, 설정 명령어 정규화
  - 정지 우선(한 후보 안, 후보끼리)
  - 후보 5개 확인(두 번째 이후 후보 통과, 6번째 후보 무시, 일부 후보만 규칙 통과)
  - 짧은 발화 규칙(2자 경계, 설정값 0·3, 정지·시작 명령어 모두 빼기)
  - 상태별 통과 규칙(재생 중·정지·준비 전 × 정지·시작·구절)
  - 중복 방지(799ms 무시, 800ms 통과, 직전 명령 없음, 앞 단계 이유 우선)
  - PoC 오인식 2건 회귀(재생 중·정지 상태 모두 `short-rule`)
- 공용 파일(`package.json`, `types.ts` 등)은 수정하지 않았다. `src/ui`, 어댑터, `poc/`도 건드리지 않았다.

### PoC 회귀 테스트 입력에 대해

저장소에 가사를 넣지 않는 규칙에 따라 이슈에 적힌 조각만 썼다. PoC 로그에서 두 발화의 정규화 후 길이만 확인했다(10자, 9자). 테스트는 `poc/` 파일을 읽지 않는다.

- "…시작을 하다 보면": 조각 그대로 나머지가 5자라 `short-rule`이다.
- "시작이고…": 조각만으로는 나머지가 "이고" 2자여서 기본 기준(2자 초과)에 걸리지 않는다. 실제 발화는 "…" 뒤에 가사가 이어진 9자였으므로, 테스트에서는 그 자리를 가사가 아닌 자리표시 글자("가나다라마")로 채워 실제 길이에 맞췄다. 즉 "시작이고"까지만 인식되는 경우는 이 규칙으로 막지 못한다.

## 5. 검증 결과

- `npm test`: 테스트 파일 9개, 테스트 147개 통과. 이 중 이번에 추가한 `commandMatcher.test.ts`·`normalize.test.ts` 2개 파일 40개 통과
- `npm run lint`: 오류 없음
- `npm run build`: `tsc -b`와 `vite build` 통과
- 이슈 인수 조건별 확인(모두 단위 테스트로 확인)
  - 순수 함수 `decide`가 `Decision`을 돌려줌: 확인. 단, 인자에 `now`를 추가했다(3장 참고)
  - 정지 우선: 확인
  - 후보 최대 5개 정규화, 하나라도 만족하면 통과: 확인
  - 나머지 2자 초과 시 `short-rule`: 확인
  - 상태별 통과 규칙: 확인
  - 0.8초 `debounce`: 확인
  - PoC 오인식 2건 회귀 테스트: 확인. 단, "시작이고…"는 자리표시 글자로 길이를 맞춘 입력이다(4장 참고)
- 수행하지 않은 검증(미확인)
  - 실제 음성 인식 결과와 컨트롤러를 연결한 동작: speechAdapter(#9)와 컨트롤러가 아직 연결되지 않아 확인하지 못했다.
  - PRD F2-2의 정지 성공률(재생 중 10번 중 9번, 노래 중 10번 중 7번)과 반응 시간: 실제 기기 측정이 필요해 확인하지 못했다.
  - PoC 로그 전체를 `decide`에 넣어 다른 발화가 바뀌지 않는지: 로그에 가사가 들어 있어 이번 테스트에 쓰지 않았다(#19에서 처리 방식을 정하는 중).

## 6. 남은 작업 / 보류 사항

- 컨트롤러는 `decide`가 `stop`·`start`·`phrase`를 돌려줘 실제로 실행한 시각을 `lastCommandAt`으로 넘겨야 한다. `now`와 같은 시계(`performance.now()` 등)를 써야 한다.
- 정지 즉시 실행(F2-6)에서 중간 결과로 `decide`를 부르는 방식과 "같은 발화에서는 한 번만 실행"은 speechAdapter·컨트롤러에서 정한다.
- 인식이 "시작이고"처럼 명령어 뒤 2자 이하로 끊기면 시작 명령으로 판별된다. 실사용에서 문제가 되면 기본값 조정(#15 등)을 검토한다.
