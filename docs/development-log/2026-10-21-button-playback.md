# 2026-10-21 버튼 재생·정지 (#7)

## 1. 배경 / 문제

- PRD F1-5: 재생 버튼은 선택한 구간의 시작 위치에서 프리롤(F2-7)만큼 앞부터 재생하고, 정지 버튼은 재생을 멈춘다. 이슈 #7은 여기에 "영상 화면을 직접 눌러 재생·정지해도 앱 상태가 어긋나지 않음"과 단계 1 완료 기준(마킹한 구간이 버튼 조작으로 시작 위치부터 재생됨)의 직접 확인을 더했다.
- main에는 상태 머신(`src/core/playbackMachine.ts`, #4), 플레이어 어댑터(#3), 구간 마킹·선택(#6), 설정 패널(#14)이 있지만, 플레이어 이벤트는 영상 불러오기 상태(`videoLoadReducer`)에만 들어가고 재생 상태로는 이어지지 않았다. 고른 연습 구간도 `SectionPanel` 안에만 있어 바깥에서 알 수 없었다.
- 같은 시기에 #17(가사 매핑 편집)이 별도 세션에서 `App.tsx`·`PlayerView`를 건드릴 수 있어, 공용 파일 변경은 최소로 해야 했다.

## 2. 검토한 선택지

- **재생 상태를 바꾸는 시점**
  - 버튼을 누를 때 컨트롤러가 직접 '재생 중'으로 바꾸기: 버튼은 즉시 반응하지만, 자동재생이 막히거나 영상 화면을 직접 누르면 실제 플레이어와 어긋난다.
  - 플레이어 이벤트(onStateChange)만 기준으로 삼기: 기술 설계 문서의 "상태의 기준"과 같고, 버튼·영상 화면·(이후) 음성 명령이 모두 같은 경로로 상태를 바꾼다.
- **플레이어 이벤트를 재생 상태로 넘기는 방법**
  - `PlayerView`에 재생 상태용 콜백을 새로 받기: `PlayerView`를 고쳐야 하고 #17과 겹칠 수 있다.
  - `App`이 `PlayerView`에 넘기는 `dispatch`를 감싸, 영상 불러오기 상태와 재생 상태에 함께 보내기: `PlayerView`는 그대로 둔다. 감싼 함수가 렌더마다 바뀌면 `PlayerView`의 효과가 다시 실행돼 플레이어를 다시 만들므로 `useCallback`으로 고정해야 한다.
- **고른 구간을 재생 버튼에 전달**
  - `SectionPanel`에 선택 알림 콜백(`onSelect`)을 선택 항목으로 추가
  - 구간 상태(`useSections`)를 `App`으로 끌어올리기: `SectionPanel`의 구조를 크게 바꿔야 한다.
- **프리롤 읽기**: 설정 패널의 `onChange`로 받아 `App`이 들고 있기와, 재생 버튼을 누를 때마다 `singcue:settings`를 읽기.

## 3. 결정 및 이유

- 재생 상태는 플레이어 이벤트만으로 바꾼다. 버튼은 `seekTo` + `play`, `pause`만 플레이어에 명령하고 상태는 건드리지 않는다. 그래서 영상 화면을 직접 눌러도 버튼과 같은 결과가 된다.
- 어댑터 이벤트 → 상태 머신 이벤트 변환(`ready` → `loaded`, `stateChange` playing/stopped → `playing`/`paused`, `error` → `error`)은 컨트롤러(`src/controller/playback.ts`)에 둔다. #4 메모대로 core와 어댑터가 서로 의존하지 않게 하기 위해서다.
- `App`에서 `dispatch`를 감싸는 방식을 택했다. `PlayerView`는 수정하지 않았다. 새 영상을 불러오면(`request`) 재생 상태를 준비 전으로 돌리고 고른 구간을 비운다. `SectionPanel`이 영상 준비 전에는 빠졌다가 다시 만들어져 선택이 사라지기 때문이다.
- `SectionPanel`에는 선택 항목 `onSelect`만 추가했다. 구간 상태는 지금처럼 패널이 가진다.
- 프리롤은 재생 버튼을 누를 때 저장소에서 읽는다. 설정 패널과 연결할 코드 없이 저장한 값이 다음 재생에 바로 반영된다. `storage.ts`는 수정하지 않았다(`loadSettings()` 사용).
- 재생 버튼은 준비 전이거나 구간을 고르지 않았을 때 비활성, 정지 버튼은 재생 중일 때만 활성이다. 재생 중에 재생 버튼을 누르면 구간 처음(프리롤 적용)부터 다시 재생한다. 음성 명령(F2-4)은 재생 중 시작 명령을 무시하지만, 버튼은 사용자가 명시적으로 누른 것이라 되감기로 쓰는 편이 자연스럽다고 판단했다.
- 구간 끝 감지·자동 정지(F2-8)는 이슈 #7 범위가 아니라 넣지 않았다.

## 4. 구현 내용

- `src/controller/playback.ts`: `toMachineEvent()`, `canPlay()`, `canStop()`, `playSection()`(프리롤 위치로 `seekTo` 후 `play`, 이동 위치 반환). 순수 함수.
- `src/controller/usePlayback.ts`: `usePlayback(playerRef, storage)` → `{ state, onPlayerEvent, unload, play(section), stop() }`. `onPlayerEvent`·`unload`는 렌더마다 같은 함수.
- `src/controller/playback.test.ts`: 이벤트 변환, 영상 화면 직접 조작 순서, 버튼 활성 조건, 프리롤 위치(기본 1.5초, 0초 제한, 프리롤 0).
- `src/ui/PlaybackControls.tsx`: 재생·정지 버튼과 상태 표시(준비 전/정지/재생 중, 연습 구간). `app.css`에 `.playback` 스타일.
- `src/ui/SectionPanel.tsx`: 선택 항목 `onSelect` 추가.
- `src/ui/App.tsx`: `usePlayback` 연결, `dispatch` 감싸기, 고른 구간 상태, `PlaybackControls` 배치(영상 준비 후 구간 패널 위).

**미확인**

- 자동재생 차단으로 재생 버튼을 눌러도 재생되지 않는 경우: 이번 브라우저에서는 막히지 않았다. 이 경우 상태는 플레이어 이벤트를 따르므로 "정지"로 남는다고 예상하지만 직접 보지 않았다.
- 재생 중 플레이어 오류(onError)로 준비 전이 되는 흐름: 테스트로만 확인했다.
- 영상이 끝까지 재생된 뒤(ended)의 상태: 테스트(상태 머신)로만 확인했다.
- `usePlayback` 훅과 `PlaybackControls` 화면의 자동 테스트: 화면 테스트 환경이 없어 순수 함수 테스트와 브라우저 확인으로 대신했다.
- 375px 폭의 화면 모양은 가로 스크롤 여부만 확인했고 스크린숏으로 보지 않았다.
- Chrome 정식 브라우저, 다른 브라우저, 실제 모바일 기기

## 6. 남은 작업 / 보류 사항

- 구간 끝 감지와 끝 동작(F2-8)은 별도 이슈에서 다룬다. 지금은 재생 버튼으로 시작하면 구간 끝을 지나도 계속 재생된다.
- 자동재생 차단 안내(기술 설계 문서 "오류 처리")는 음성 시작 명령과 함께 다룬다.
- 고른 연습 구간은 저장하지 않는다(#6 결정과 같음). 새로고침하면 다시 골라야 한다.
