# 2026-10-21 음성 제어 연결(useVoice)과 음성 패널 (#11)

## 1. 배경 / 문제

- PRD F2-1~F2-4와 비기능 요구사항(프라이버시): 음성 인식을 버튼으로 켜고 끄고, 켜면 마이크 장치 이름과 입력 레벨을 보이고, 정지·시작 명령으로 재생을 제어하며, 무시한 발화는 이유와 함께 "무시"로 표시한다. 마이크 권한 거부, 자동재생 차단(시작 명령 후 3초), 음성이 브라우저 제공사 서버로 전송될 수 있다는 안내도 필요하다.
- main에는 판별(`commandMatcher.decide`, #8), 인식(`speechAdapter`, #9), 마이크 측정(`micMeter`, #10), 버튼 재생·정지(`usePlayback`, #7)가 각각 있었지만 서로 이어지지 않았다.
- 같은 시기에 #18(백업) 세션이 `storage.ts`·`SettingsPanel.tsx`를, 이후 #13(구간 끝 동작) 세션이 `usePlayback.ts`·`playback.ts`·`playbackMachine.ts`를 고친다. 그래서 이 작업은 `App.tsx`와 새 파일(`useVoice.ts`, `VoicePanel.tsx`, `VoicePanel.css`, 테스트, 이 기록)만 고치기로 범위를 정했다.

## 2. 검토한 선택지

- **최신 재생 상태·구간을 인식 콜백에서 읽는 방법**
  - 렌더마다 ref에 최신 값을 써 두기: lint(react-hooks 7)의 ref 규칙에 걸리고, 효과에서 옮겨 적으면 한 프레임 늦을 수 있다.
  - 인식 어댑터를 마운트 때 한 번 만들고, 리스너는 `useEffectEvent`로 감싸기: 항상 최신 렌더의 값을 읽고 어댑터를 다시 만들 필요가 없다.
- **자동재생 차단 감시 위치**: `usePlayback`에 넣기와 `useVoice`에서 재생 상태를 지켜보기. 앞의 방법은 #13 세션과 파일이 겹쳐 뒤의 방법을 택했다.
- **감시 상태를 지우는 방법**: 효과 안에서 `setState`하기(react-hooks 7의 set-state-in-effect 규칙에 걸림)와, 렌더 중에 조건부로 상태를 조정하기.
- **마이크 측정과 인식의 순서**: 인식만 켜고 측정은 따로 하기와, 측정기(`startMicMeter`)로 먼저 권한을 받은 뒤 인식을 켜기.

## 3. 결정 및 이유

- 판별은 `decide()`에 맡기고, `useVoice`는 결과만 따라 `usePlayback`의 `stop()`·`play(section)`을 부른다. 프리롤은 `play()`가 `singcue:settings`에서 읽으므로 따로 계산하지 않는다. `usePlayback.ts`·`playback.ts`는 고치지 않았다.
- 명령어·짧은 발화 기준·정지 즉시 실행 설정은 인식 결과가 올 때마다 `storage.loadSettings()`로 읽는다. `usePlayback`의 프리롤과 같은 방식이라 설정 패널에서 저장한 값이 다음 발화에 바로 반영된다.
- 중간 결과는 정지 즉시 실행(`stopOnInterim`)이 켜져 있을 때 정지 명령만 판별한다. 명령을 실행한 발화 ID는 기억해 같은 발화의 뒤따르는 결과(최종 결과 포함)는 다시 판별하지 않는다(기술 설계 문서 "같은 발화에서는 한 번만 실행"). 중간 결과의 무시는 기록하지 않는다. 같은 발화의 중간 결과가 여러 번 와서 기록이 넘치기 때문이다.
- 직전 명령 시각(`lastCommandAt`)은 실제로 정지·시작을 실행했을 때만 갱신한다. 무시한 발화로 다음 명령이 막히지 않게 하기 위해서다.
- 시작 명령인데 연습 구간을 고르지 않았으면 재생하지 않고 "무시"로 이유를 남긴다. `decide`의 무시 이유 4가지에는 없는 경우라 컨트롤러가 따로 처리한다.
- 구절(`phrase`) 판별은 구절 점프(F4)가 아직 없어 "구절"로 표시하고 "아직 지원하지 않음"이라고 적는다. 정지 상태에서 노래 가사를 말해도 아무 동작도 하지 않는다.
- 마이크 측정기로 먼저 권한을 받는다. 거부되면 micMeter의 안내 문구("…버튼 조작은 계속 쓸 수 있습니다")를 보이고 인식을 켜지 않는다. 측정이 열리면 장치 이름을 보이고 인식을 켠다. 켜는 도중 끄면 늦게 열린 측정기는 바로 닫는다.
- 자동재생 차단: 시작 명령을 실행할 때마다 번호를 붙이고, 재생 상태가 아니면 3초 타이머를 건다. 시간이 지나면 그 번호를 기록하고, 안내는 "번호가 같고 아직 재생 상태가 아님"일 때만 보인다. 재생 상태가 되면(재생 버튼을 눌러도) 렌더 중에 감시를 끝낸다.
- 음성 패널은 영상을 불러오기 전에도 보인다. 그때 들어온 명령은 상태 규칙(준비 전)에 따라 이유와 함께 무시로 표시된다.
- 스타일은 `VoicePanel.css`에 두고 `app.css`는 고치지 않았다. 공용 클래스 `.message`, `.message--error`, 변수 `--border`는 그대로 쓴다.

## 4. 구현 내용

- `src/controller/useVoice.ts`
  - 순수 함수: `voiceReducer`(켜짐 상태, 장치 이름, 입력 레벨, 들은 말, 오류, 무음 안내, 판별 기록 최대 10개), `judgeResult`(중간·최종 결과와 실행한 발화 처리 후 `decide` 호출), `ignoreReasonText`(무시 이유 문장), `isAutoplayBlocked`
  - 훅 `useVoice({ playback, section, storage })` → 상태 + `supported`, `autoplayBlocked`, `enable()`, `disable()`. 인식 어댑터는 마운트 때 만들고 해제 때 인식·마이크를 모두 끈다.
- `src/ui/VoicePanel.tsx`, `src/ui/VoicePanel.css`: 프라이버시 안내, 미지원 안내, 켜기·끄기 버튼과 상태(꺼짐/켜는 중/듣는 중)·마이크 이름, 입력 레벨(`<meter>`와 dB), 오류·무음·자동재생 차단 안내, 들은 말, 판별 기록(정지/시작/구절/무시와 이유)
- `src/ui/App.tsx`: `useVoice` 연결, 설정 패널 위에 `VoicePanel` 배치
- `src/controller/useVoice.test.ts`: 테스트 16개

## 5. 검증 결과

- `npm run lint`: 오류·경고 없음
- `npm run build`: 통과

**실제 브라우저 확인** (앱 내 브라우저, Chromium 계열, `vite --port 5197`로 띄운 `http://localhost`, 영상 `dQw4w9WgXcQ`, 0:20~0:40 구간 1)

- 프라이버시 안내 문구가 음성 패널에 보임
- **마이크 권한 거부**: 앱 내 브라우저는 마이크를 막아 둔다. "음성 인식 켜기"를 누르면 상태 "꺼짐"과 "마이크 권한이 거부되어 음성 인식을 켜지 못했습니다. … 버튼 조작은 계속 쓸 수 있습니다." 안내가 보임. 이어서 구간 1을 고르고 재생 버튼 → "재생 중", 정지 버튼 → "정지"로 버튼 조작이 그대로 동작함
- 아래 항목은 **실제 마이크·음성이 아니라** 페이지에 가짜 `getUserMedia`(오실레이터 소리를 낸 스트림)와 가짜 `SpeechRecognition`(스크립트로 인식 결과를 넣음)을 넣어 확인했다. 플레이어와 앱 코드는 실제 것이다.
  - 켜기 → "듣는 중 · 마이크: MediaStreamAudioDestinationNode", 입력 레벨 −29dB 표시. 끄기 → "꺼짐", 입력 레벨 숨김
  - 정지 상태에서 "시작" → "재생 중", 1.5초 뒤 위치 19.7초(구간 시작 20초 − 프리롤 1.5초 = 18.5초부터 재생한 것과 맞음). 기록 "시작"
  - 재생 중 "멈춰" → "정지". 기록 "정지"
  - 정지 상태 "멈춰" → 무시("정지 상태에서는 받지 않는 명령입니다"), "이제 시작하는 우리 이야기" → 무시("명령어를 뺀 나머지가 2자를 넘어 가사로 봤습니다"), "시작" 직후 0.4초 만의 "멈춰" → 무시("직전 명령 후 0.8초 안의 명령입니다"), 1.2초 뒤 "스톱" → 정지. 명령어 없는 발화 → "구절"(아직 지원하지 않음)
  - **자동재생 차단**: iframe으로 가는 `playVideo` 메시지를 가로채 버린 상태에서 "시작" → 1.5초에는 안내 없음, 3.5초에 "시작 명령 후 3초가 지나도 재생되지 않았습니다. … 재생 버튼을 한 번 눌러 주세요." 표시. 재생 버튼을 누르면 "재생 중"이 되고 안내가 사라지며, 다시 정지해도 안내가 돌아오지 않음. 재생이 정상일 때는 안내가 뜨지 않음
- 콘솔 오류 없음, 375px 폭에서 가로 스크롤 없음(`scrollWidth` 375)

**미확인**

- 실제 마이크로 장치 이름·입력 레벨이 보이는지, 실제 음성으로 정지·시작 명령이 실행되는지: 앱 내 브라우저가 마이크를 막아 가짜 장치·가짜 인식으로만 확인했다. Chrome 정식 브라우저에서 사람이 직접 확인해야 한다.
- 실제 Web Speech API의 자동 재시작, `no-speech`·`network` 오류 안내, 무음(−55dB 4초) 안내: 리듀서 테스트로만 확인했다.
- 정지 즉시 실행(중간 결과) 동작: `judgeResult` 테스트로만 확인했다.
- 실제 자동재생 정책으로 막히는 경우: 메시지를 가로채 흉내 냈을 뿐 브라우저 정책으로 막힌 상황은 보지 못했다.
- 반응 시간(정지 0.1초, 재생 0.5초 이내)과 인식률(PRD F2-2): 측정하지 않았다.
- `useVoice` 훅과 `VoicePanel` 화면의 자동 테스트: 화면 테스트 환경이 없어 순수 함수 테스트와 브라우저 확인으로 대신했다.
- 375px 폭은 가로 스크롤 여부만 확인했고 스크린숏으로 보지 않았다.

## 6. 남은 작업 / 보류 사항

- 구절 인식 점프(F4)는 별도 이슈에서 `phrase` 판별에 연결한다.
- 정지 즉시 실행 기본값은 반응 시간을 측정해 정한다(#15).
- 연습 기록(F5)과 구간 끝 동작(F2-8, #13)은 이 작업에 넣지 않았다. #13에서 구간 끝 자동 반복이 들어오면 자동재생 차단 감시와 겹치지 않는지 다시 볼 필요가 있다.
