# 2026-10-21 가사·음원 미포함 규칙과 예시 데이터 (#19)

## 1. 배경 / 문제

- PRD F3-5와 비기능 요구사항(저작권)은 저장소와 배포물에 가사·음원을 넣지 않고, 예시 데이터는 직접 만든 가상의 구절만 쓰도록 정했다.
- 저장소에는 README가 없었고, `.gitignore`에는 음원·영상 파일이나 사용자 내보내기 파일에 대한 규칙이 없었다.
- `poc/poc_log_261021.json`(첫 커밋부터 포함)에는 실제 곡을 부르며 인식된 가사 문장과, 사용자가 입력한 가사 줄 3개가 그대로 들어 있었다. 저장소는 공개(public) 상태다.
- 이 로그는 #8(commandMatcher)의 회귀 테스트, #21·#23(phraseMatcher, 유사도 기준)의 수치 근거로 쓰인다. 특히 가사가 시작 명령으로 오인될 뻔한 2건은 짧은 발화 규칙(명령어를 뺀 나머지 글자 수)의 근거라 분석 정보가 남아야 했다.

## 2. 검토한 선택지

- **PoC 로그 처리**
  - 저장소에서 제외(삭제 후 `.gitignore`): 가장 단순하지만 PRD·설계 문서가 인용하는 수치(반응 시간, 유사도 0.50~0.89, 오인식 2건)의 근거가 저장소에서 사라진다.
  - 가사 부분만 지우고 남기기: 수치와 판별 결과는 그대로 두고 문장만 바꾼다. 오인식 2건은 문장을 지우면 회귀 테스트에 쓸 입력이 없어진다.
  - 오인식 2건만 직접 만든 가상 문장으로 바꾸기: 짧은 발화 규칙이 보는 특징(명령어 위치, 명령어를 뺀 나머지 글자 수)을 원문과 같게 맞추면 테스트 입력으로 그대로 쓸 수 있다.
- **사용자 내보내기 파일 이름**: JSON 백업(#18)은 아직 구현 전이라 파일 이름이 정해지지 않았다. 모든 `*.json`을 막으면 설정 파일과 예시 데이터까지 막혀서, 앱 이름으로 시작하는 패턴만 막기로 했다.

## 3. 결정 및 이유

- PoC 로그는 **같은 파일 이름으로 두고 가사 부분만 지운다**. 다른 문서와 이슈가 이 경로를 가리키고 있어 이름을 바꾸지 않았다.
  - 가사 인식 결과(최종 결과와 대안)는 `[가사 제거 · N자]`로 바꿨다. N은 공백과 기호를 뺀 글자 수로, 구절 매칭 분석에 필요한 길이 정보만 남긴다. 항목에 `redacted: "lyrics"`를 붙였다.
  - 사용자가 입력한 가사 줄 3개는 라벨 `L1`~`L3`로 바꾸고, 각 줄의 글자 수는 맨 앞 `redaction.lines`에 적었다. 인식 결과 항목에는 바로 다음 구절 판정이 가리킨 줄을 `lineRef`로 붙였다. 유사도, 기준, 이동 시간, 이동 여부는 원문 그대로다.
  - 시작 명령 오인식 2건(`ignored` 항목과 그 인식 결과)은 직접 만든 가상 문장으로 바꾸고 `redacted: "fictional-substitute"`를 붙였다. 어절 수와 어절별 글자 수, 명령어 "시작"의 위치(문장 처음인지), 명령어를 뺀 나머지 글자 수(`original.restChars`: 7, 6)가 원문과 같다. 대안 후보 개수도 같다.
    - 1건: "작은 시작을 쌓아 가면" (명령어가 문장 중간, 나머지 7자)
    - 2건: "시작이고 내일이며" (명령어가 문장 처음, 나머지 6자)
  - 정지 명령어 "멈춰"와 한 글자 다른 낱말로 시작한 가사 1건은 문장을 지우고 그 사실만 `note`에 적었다. "멈"/"춰"가 두 발화로 나뉜 경우는 명령어 조각 "춰"만 남겼다.
  - 명령어 인식 결과("시작", "stop", "멈춰", "음악 큐" 등), 신뢰도, 지연 시간, 통계, 설정, 기기 정보는 바꾸지 않았다.
- 실제 가사 원문은 이 기록, README, PR 본문에도 적지 않는다.
- **git 히스토리**: 원문 로그는 첫 커밋(`6fa11ff`)에 남아 있어, 이번 변경으로는 최신 트리에서만 사라진다. 공개 저장소에서 완전히 지우려면 히스토리 재작성과 force push가 필요하다. 모든 브랜치·PR·다른 작업 worktree에 영향을 주므로 이번 작업에서는 하지 않았고, 사용자 판단으로 남겼다(6절).
- `.gitignore`에는 음원(`mp3`, `wav`, `flac`, `aac`, `m4a`, `ogg`, `oga`, `opus`, `wma`, `aif`, `aiff`), 영상(`mp4`, `m4v`, `mkv`, `webm`, `mov`, `avi`, `wmv`, `flv`, `3gp`), 가사·자막(`lrc`, `srt`, `vtt`) 확장자를 넣었다. `.ts`(MPEG-TS)는 TypeScript 파일과 겹쳐 넣지 않았다.
- 사용자 내보내기 파일은 `singcue-backup*.json`, `singcue-export*.json`을 막았다. #18에서 내보내기 파일 이름을 이 패턴 중 하나로 정해야 이 규칙이 의미가 있다.
- 새로 내려받는 PoC 로그(`poc/poc_log_*.json`)는 가사가 들어 있으므로 막고, 가사를 지운 `poc/poc_log_261021.json`만 예외로 두었다.
- 예시 데이터는 `examples/sample-video.json` 하나로, `VideoData` 형식(구간 2개, 직접 지은 가상의 구절 6줄, `endT`)을 따른다. 영상 ID `sampleVid01`도 가상의 값이다. 예시를 검사하는 테스트는 Vitest `include`(`src/**`)를 바꿔야 해서, 다른 이슈와 공용 설정 충돌을 피하려고 추가하지 않았다(5절의 1회성 확인으로 대신함).

## 4. 구현 내용

- `poc/poc_log_261021.json`: 위 규칙으로 가사를 지우고 맨 앞에 `redaction`(방식, 규칙, 줄별 글자 수)을 추가했다. 변환에 쓴 스크립트는 저장소에 두지 않았다(원문 가사를 매핑 표로 담고 있어서).
- `.gitignore`: 음원·영상·가사 파일, 사용자 내보내기 파일, 새 PoC 로그 규칙 추가
- `README.md`(새 파일): 프로젝트 소개, 개발 명령, "가사·음원 미포함 규칙"
- `examples/sample-video.json`(새 파일): 가상의 예시 데이터
- `src/`는 다른 이슈가 병렬로 작업 중이라 수정하지 않았다.

## 5. 검증 결과

- `npm test`: 테스트 파일 7개, 테스트 107개 통과
- `npm run lint`: 오류 없음
- `npm run build`: `tsc -b`와 `vite build` 통과. `dist`에는 `index.html`과 JS 번들 하나만 있고, 음원·영상·JSON 파일과 PoC 로그·예시 데이터·가사 문자열이 없음을 확인했다.
- 가사 제거: 원문 가사에서 뽑은 낱말들로 `git grep`(작업 트리의 추적 파일)과 `dist`를 검색해 결과가 없음을 확인했다. 같은 검색어로 `git log -S`를 하면 첫 커밋 `6fa11ff`만 나온다(히스토리에는 남아 있음).
- 오인식 2건의 가상 문장: 공백·기호를 지우고 "시작"을 뺀 나머지 글자 수가 7, 6으로 원문과 같고 기본값 2자를 넘는다(스크립트로 확인).
- `.gitignore`: `git check-ignore`로 `a.mp3`, `x/b.webm`, `song.lrc`, `singcue-backup-20261021.json`, `poc/poc_log_261022.json`은 무시되고, `poc/poc_log_261021.json`, `src/types.ts`, `examples/sample-video.json`은 무시되지 않음을 확인했다.
- 예시 데이터: 임시 테스트로 `createStorage`의 `saveVideo` → `loadVideo`를 거쳐도 값이 그대로임을 확인했다(형식이 틀린 구간·구절이 없음). 임시 테스트 파일은 삭제했다.

**미확인**

- git 히스토리(`6fa11ff`)와 GitHub에 이미 남은 원문: 지우지 않았고, 포크·클론·캐시에 복사본이 있는지는 확인할 수 없다.
- #8의 회귀 테스트가 가상 문장을 쓰는지: #8은 병렬로 진행 중이고, 이슈 본문은 원문 일부를 인용한다. 그쪽 테스트 코드에 원문이 들어가는지는 확인하지 않았다.
- 내보내기 파일 이름 규칙이 실제 내보내기와 맞는지: #18 구현 전이라 확인하지 못했다.

## 6. 남은 작업 / 보류 사항

- **히스토리에서 원문 제거(사용자 결정 필요)**: 공개 저장소에서 원문을 완전히 지우려면 모든 브랜치가 병합된 뒤 `git filter-repo --path poc/poc_log_261021.json --invert-paths`(또는 이 PR의 가사 제거 판으로 바꾸는 `--blob-callback`)로 히스토리를 다시 쓰고 `git push --force --all`을 해야 한다. 그 전에 열린 PR과 작업 worktree를 정리해야 하고, 모든 클론을 다시 받아야 한다. GitHub에 남은 캐시·PR 화면의 이전 커밋은 GitHub 지원 요청으로 지워야 할 수 있다.
- #8 회귀 테스트는 원문 대신 이 로그의 가상 문장 2개를 입력으로 쓰는 것이 이 규칙과 맞다.
- #18 내보내기 파일 이름은 `singcue-backup-<날짜>.json` 같이 `.gitignore` 패턴에 맞춘다.
- 가사 텍스트는 확장자로 막을 수 없으므로, 커밋 전 확인은 사람이 해야 한다. 필요하면 이후 검사 스크립트나 CI 확인을 검토한다.
