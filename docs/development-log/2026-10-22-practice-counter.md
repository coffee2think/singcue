# 2026-10-22 연습 1회 판정 practiceCounter (#26)

## 1. 배경 / 문제

- PRD F5-1은 구간 재생이 최소 재생 시간(기본 3초) 이상 이어질 때만 연습 1회로 기록하도록 요구한다. 기술 설계 문서의 "연습 기록 시점"은 재생 중 → 정지 전이 때 판정하도록 정했다.
- #24 결정으로 자동 반복은 바퀴마다 1회로 센다. 자동 반복 중에는 재생 중 → 정지 전이가 일어나지 않으므로, `practiceCounter`가 "바퀴 완료" 입력을 하나 더 받아야 한다.
- 바퀴 완료 이벤트는 #13이 다른 세션에서 동시에 `usePlayback`에 만들고 있고, 판정 결과를 저장하고 화면·훅에 연결하는 일은 #27 범위다. 그래서 이번에는 `src/core`의 순수 로직만 만들고, #27에서 연결하기 쉬운 입력 형태를 정해야 했다.

## 2. 검토한 선택지

- **입력 형태**
  - 재생 상태(`PlaybackState`) 전이를 그대로 받기: `playbackMachine`과 바로 이어지지만, 어떤 구간을 재생 중인지와 시각을 따로 넘겨야 하고 바퀴 완료를 표현할 수 없다.
  - 판정에 필요한 사건만 담은 이벤트(`start`·`lap`·`stop`)를 core에 정의하기: 컨트롤러가 상태 전이와 #13의 바퀴 완료를 이 형태로 바꿔 넘기면 된다. `playbackMachine`의 `PlayerEvent`와 같은 방식이다.
- **재생 시간 계산**
  - 이벤트마다 재생 시간(초)을 받기: 플레이어 시각 기준으로 정확하지만, 호출하는 쪽이 바퀴 시작을 기억해야 해서 판정 로직이 컨트롤러로 새어 나간다.
  - 이벤트에 시각(`Date.now()` 기준 ms)만 받고 core가 바퀴 시작 시각과의 차로 계산하기: 상태를 core가 들고 있어 테스트로 전부 확인할 수 있다. 버퍼링 시간도 들어가지만, `playbackReducer`가 버퍼링을 재생 중으로 보므로 같은 기준이다.

## 3. 결정 및 이유

- 입력 이벤트 타입 `PracticeEvent`를 `src/core/practiceCounter.ts`에 정의했다. core는 어댑터·React에 의존하지 않아야 하므로 타입을 core에 둔다.
  ```ts
  type PracticeEvent =
    | { type: 'start'; at: number; videoId: string; sectionId: string | null } // 재생 중으로 바뀜
    | { type: 'lap'; at: number }   // 자동 반복의 바퀴 완료(#13)
    | { type: 'stop'; at: number }; // 재생 중에서 정지·준비 전으로 바뀜
  ```
  시각 `at`은 `Date.now()` 기준 ms, 최소 재생 시간과 결과의 `seconds`는 초 단위다. 작업 지시의 권장 형태를 그대로 따랐다.
- 재생 시간은 바퀴 시작 시각과 이벤트 시각의 차로 core가 계산한다(위 선택지 2). 프리롤 위치부터 재생한 시간도 그대로 포함되므로 #24의 "`seconds`는 프리롤 포함 실제 재생 시간"과 맞는다.
- #24 결정 반영
  - `lap`: 끝난 바퀴에 최소 재생 시간 규칙을 적용해 기록하고, 다음 바퀴 시작 시각을 그 시점으로 다시 잡는다. 기록되지 않은 짧은 바퀴의 시간은 다음 바퀴로 넘기지 않는다(바퀴마다 같은 규칙을 적용한다는 결정을 그대로 해석).
  - `stop`: 마지막 바퀴(재생 시작 또는 마지막 바퀴 완료 이후)에 같은 규칙을 적용한다. 자동 정지와 자동 반복 모두 같은 경로다.
- 이슈·문서에 정해지지 않아 이번에 정한 세부 규칙
  - `PracticeRecord.at`은 바퀴를 **시작한** 시각으로 했다. 연습한 때를 나타내는 값이라 판정 시각보다 시작 시각이 자연스럽다고 봤다. 날짜별 추이(F5-3)에서 자정을 걸친 바퀴만 차이가 난다.
  - `start`의 `sectionId`가 `null`이면(구간을 고르지 않고 영상만 재생) 기록하지 않는다. `PracticeRecord.sectionId`가 필수이고 F5-1이 "구간 재생"을 대상으로 하기 때문이다.
  - 재생 중에 `start`가 다시 오면(구절 이동 등으로 재생 중에 구간이 바뀌는 경우) 이전 바퀴를 정지처럼 닫아 판정하고 새 바퀴를 시작한다.
  - 재생 중이 아닐 때의 `lap`·`stop`은 무시한다. 시각이 거꾸로 들어오면 재생 시간을 0초로 본다.
- 결과는 `records` 배열로 돌려준다. 재생 중 구간이 바뀌는 경우를 빼면 0개 또는 1개지만, 호출하는 쪽이 저장할 목록을 그대로 쓰도록 배열로 통일했다.
- `PracticeRecord`는 `src/types.ts`의 타입을 그대로 썼고, `src/types.ts`는 고치지 않았다.

## 4. 구현 내용

- `src/core/practiceCounter.ts`
  - `PracticeEvent`, `PracticeCounterState`(진행 중인 바퀴의 영상·구간·시작 시각, 재생 중이 아니면 `null`), `INITIAL_PRACTICE_COUNTER_STATE`
  - `isPractice(seconds, minPracticeSeconds)`: 최소 재생 시간 이상인지
  - `practiceCounterReducer(state, event, minPracticeSeconds)`: `{ state, records }`를 돌려주는 순수 함수
- `src/core/practiceCounter.test.ts`: 20개 테스트
  - 재생 중 → 정지: 5초 기록, 정확히 3초 기록, 2.999초 미기록, 설정값(1초·10초) 반영, `at` 형식, 여러 번 재생·정지, 구간 없는 재생 미기록, 재생 중이 아닐 때 입력 무시, 시각 역전, 알 수 없는 이벤트
  - 재생 중 구간 변경: 이전 바퀴 판정 후 새 구간으로 시작
  - 자동 반복: 바퀴마다 9.5초(프리롤 1.5초 포함)로 1회씩 기록하고 시작 시각을 다시 잡음, 반복 중 정지 시 마지막 바퀴 판정(4초 기록, 1.5초 미기록), 짧은 바퀴(2초)는 기록하지 않고 시간을 넘기지 않음, 바퀴 완료 직후 정지
- 저장(storage)과 화면·훅 연결은 #27 범위라 하지 않았다.

## 6. 남은 작업 / 보류 사항

- #27: 재생 상태 전이와 #13의 바퀴 완료 콜백을 `PracticeEvent`로 바꿔 넘기고, `records`를 `singcue:log`에 저장한다. 최소 재생 시간은 `singcue:settings`의 `minPracticeSeconds`를 넘긴다.
- #13의 바퀴 완료 콜백이 시각(ms)이 아니라 재생 시간 등 다른 형태로 나오면 #27에서 변환한다.
- `at`을 바퀴 시작 시각으로 둔 결정은 리포트(F5-3) 구현 때 다시 볼 수 있다.
