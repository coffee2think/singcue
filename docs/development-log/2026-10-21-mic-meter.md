# 2026-10-21 micMeter: 마이크 장치와 입력 레벨 (#10)

## 1. 배경 / 문제

- PRD F2-1은 음성 인식을 켜면 사용 중인 마이크 장치 이름과 입력 레벨이 보이고, 마이크 권한이 거부되면 안내할 것을 요구한다.
- 기술 설계 문서 "오류 처리"는 소리가 안 들어오는 상황을 "입력 레벨이 −55dB 미만으로 4초 지속"으로 감지해 장치 이름과 장치 확인 안내를 보여 주도록 정했다. PoC에서 이어폰 마이크가 잡히지 않아 겪은 문제 때문이다.
- 브라우저 의존(getUserMedia, AnalyserNode)은 어댑터 뒤에 숨긴다는 구조에 따라 `src/adapters/micMeter`에 둔다. 화면(#5)과 음성 인식(#9)은 다른 세션이 동시에 작업하므로 이번에는 어댑터와 이벤트 타입만 만들고 연결은 하지 않는다.

## 2. 검토한 선택지

- **레벨 계산에 쓸 파형**
  - `getByteTimeDomainData`(0~255): PoC가 쓴 방식이라 −55dB 기준이 PoC에서 잰 값과 같은 뜻이 된다. 다만 한 칸(1/128) 단위로 끊겨 무음 근처 값이 거칠다(모든 샘플이 한 칸 흔들리면 약 −42dB, 신호가 전혀 없으면 계산상 −∞).
  - `getFloatTimeDomainData`: 더 정밀하지만 같은 입력에서 PoC와 다른 값이 나와 −55dB 기준을 다시 검증해야 한다.
- **오류 전달 방식**
  - Promise를 거부(throw): 호출하는 쪽이 try/catch로 받는다.
  - `onEvent`로 'error'를 보내고 null을 돌려줌: playerAdapter가 오류를 이벤트로 알리는 방식과 같아 컨트롤러가 한 곳에서 처리할 수 있다.
- **측정 주기**: PoC처럼 `requestAnimationFrame`을 쓰거나 `setInterval`을 쓸 수 있다. 탭이 보이지 않을 때 멈추는 차이가 있다.

## 3. 결정 및 이유

- 바이트 파형을 쓴다. PRD·설계 문서의 −55dB가 PoC 측정에서 나온 값이라 계산을 PoC와 똑같이 맞췄다. 신호가 없을 때는 −100dB(`MIN_DB`)로 둔다.
- 오류는 'error' 이벤트로 보내고 `startMicMeter`는 null을 돌려준다. getUserMedia 오류 이름을 앱의 오류 종류로 바꾼다: NotAllowedError·SecurityError → 권한 거부, NotFoundError·OverconstrainedError → 장치 없음, NotReadableError·AbortError → 장치 사용 중, mediaDevices나 AudioContext가 없음 → 지원 안 됨(HTTPS·localhost가 아님), 그 밖 → 알 수 없음. 권한 거부 안내에는 설계 문서대로 "버튼 조작은 계속 쓸 수 있다"를 넣었다.
- 측정은 PoC처럼 `requestAnimationFrame`으로 한다. 레벨 표시는 화면이 보일 때만 의미가 있고, 연습 중에는 앱 탭을 보고 있다는 전제다. 무음 판정 시각은 rAF가 넘겨 주는 시각을 써서 테스트에서 시간을 직접 넣을 수 있게 했다.
- 무음은 −55dB **미만**이 4초 **이상** 이어진 순간 한 번만 알리고, 레벨이 −55dB 이상으로 올라오면 다시 처음부터 잰다(PoC와 같은 규칙). 판정은 브라우저 API 없는 `createSilenceDetector`로 분리해 테스트로 고정했다.
- 무음 이벤트에는 장치 이름을 함께 넣었다. 설계 문서의 처리가 "입력 장치 이름을 보여 주고 장치 확인을 안내"이기 때문이다.
- 마이크를 연 뒤 오디오 준비에 실패하면 열린 트랙과 오디오 컨텍스트를 닫는다. 브라우저 탭에 마이크 사용 표시가 남지 않게 하기 위해서다.

## 4. 구현 내용

`src/adapters/micMeter/`

- `levelMath.ts`: `byteSamplesToDb`(바이트 파형 RMS → dBFS), `createSilenceDetector`(기준 −55dB, 4초), 상수 `MIN_DB`, `SILENCE_THRESHOLD_DB`, `SILENCE_DURATION_MS`
- `micEvents.ts`: `MicEvent`(level | silence | error), `MicError`(kind, message), `toMicError`, `MIC_ERROR_MESSAGES`
- `startMicMeter.ts`: `startMicMeter(onEvent)`가 `getUserMedia({ audio: true })` → `AudioContext` → `AnalyserNode`(fftSize 1024)로 연결하고, 성공하면 `MicMeter`(deviceLabel, getLevel, stop)를 돌려준다. 장치 이름이 비어 있으면 '이름 없음'. `stop`은 rAF 취소, 트랙 정지, 컨텍스트 닫기를 하고 여러 번 불러도 된다.
- `index.ts`: 바깥에 공개하는 이름 모음

공용 파일(`package.json`, `types.ts` 등)은 바꾸지 않았다.

## 5. 검증 결과

**자동 검증**

- `npm test`: 테스트 파일 10개, 테스트 130개 통과(이번에 추가한 파일 3개, 테스트 23개)
  - `levelMath.test.ts`: dB 계산(무음, 진폭별 값, 한 칸 흔들림이 약 −42dB), 무음 판정(4초 경계, 한 번만 알림, 소리가 나면 다시 잼, 다시 무음이면 다시 알림, reset)
  - `micEvents.test.ts`: 오류 이름별 종류와 문구
  - `startMicMeter.test.ts`: navigator.mediaDevices·AudioContext·requestAnimationFrame을 **모의 객체로 바꿔** 연결 순서, 장치 이름, 레벨 이벤트, 4초 무음 이벤트, stop 정리, 권한 거부·준비 실패·미지원 오류를 확인했다. 실제 마이크 입력은 확인하지 않는다.
- `npm run lint`: 오류 없음
- `npm run build`: 통과

**실제 브라우저 확인** (앱 내 브라우저, Chromium 계열, `http://localhost`에서 커밋하지 않은 임시 확인 페이지로 `startMicMeter`를 직접 호출)

- 이 브라우저는 마이크 사용을 막아 두어 권한 상태가 `denied`였다. 이때 `startMicMeter`가 `{ kind: 'permission-denied' }` 오류와 안내 문구를 'error' 이벤트로 보내고 null을 돌려줬다. 페이지 오류는 없었다. → **마이크 권한 거부 시 오류 전달은 실제 브라우저에서 확인**

**미확인**

- 실제 마이크의 장치 이름 표시: 마이크를 쓸 수 있는 브라우저가 없어 모의 테스트로만 확인했다.
- 실제 마이크 입력의 레벨(dB) 값: 모의 파형으로 계산만 확인했다. 말할 때와 조용할 때 실제로 어떤 값이 나오는지는 확인하지 않았다.
- 실제 무음 4초 후 무음 이벤트: 모의 시각으로만 확인했다. 특히 바이트 파형에서 실제 조용한 방의 잡음이 −55dB 아래로 내려가는지(PoC에서 경고가 실제로 떴는지)는 다시 확인하지 않았다.
- 사용자가 권한 창에서 직접 "차단"을 누른 경우: 브라우저가 미리 막아 둔 경우만 확인했다. 두 경우 모두 NotAllowedError로 알려진 동작이다.
- 장치 없음(NotFoundError), 장치 사용 중(NotReadableError), HTTPS가 아닌 주소(mediaDevices 없음): 모의 테스트로만 확인
- Chrome 정식 브라우저, 이어폰(블루투스) 마이크에서의 동작

## 6. 남은 작업 / 보류 사항

- 화면(#5)에 장치 이름과 레벨 막대를 표시하고, 'silence'와 'error'를 안내로 보여 주는 연결은 하지 않았다. 'level'은 화면 갱신마다 오므로 화면 쪽에서 상태 갱신 횟수를 줄여야 할 수 있다.
- 음성 인식(#9)을 켤 때 `startMicMeter`를 함께 부르고, 끌 때 `stop`하는 연결은 컨트롤러에서 한다. 인식 오류 `not-allowed`와 마이크 권한 거부 안내를 한 번만 보여 주도록 컨트롤러에서 정리해야 한다.
- 측정 중 장치가 빠지는 경우(트랙 `ended`)는 이번 인수 조건에 없어 처리하지 않았다.
- 실제 마이크로 장치 이름, 레벨, 4초 무음 이벤트를 Chrome에서 확인해야 한다.
