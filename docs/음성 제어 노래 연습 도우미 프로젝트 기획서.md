# singcue 프로젝트 기획서 (음성 제어 노래 연습 도우미)

Oct 21, 2026 · @Louis Choi

## 프로젝트 개요

말로 멈추고 말로 시작하는 노래 연습 도우미로, YouTube 영상의 원하는 구간부터 바로 재생해 주는 웹 앱입니다.

- **배경**: 노래 연습은 어려운 구간을 반복해서 듣는 일이 많은데, 그때마다 재생바를 손으로 움직여야 해서 연습 흐름이 끊깁니다.
- **핵심 아이디어**: "잠깐, 스탑" 같은 말로 멈추고, "시작", "재생해" 같은 말이나 직전 구절을 말하는 것으로 원하는 위치부터 다시 재생합니다.
- **대상 사용자**: 노래를 연습하면서 특정 구간을 반복해서 듣는 사람.
- **용도**: 취업용 포트폴리오이며, 코드와 시연을 공개하는 것을 전제로 합니다.
- **프로젝트 이름**: singcue (시작 명령어 "음악큐"의 큐에서 따온 이름)입니다.
- **가정**: 웹 앱(브라우저) 기준으로 작성했습니다. 다른 플랫폼이면 기술 스택 섹션을 바꿔야 합니다. 음성 인식은 이어폰 사용을 전제로 합니다.

## 문제 정의 및 목표

노래 연습의 병목은 "어려운 구간으로 돌아가는 동작"이고, 이 프로젝트는 그 동작을 손이 아니라 목소리로 대체합니다.

**문제**

- 연습 중에는 같은 구간을 여러 번 반복하는데, 매번 재생바를 찾아 클릭해야 합니다.
- 악보나 가사를 보거나 악기를 다루는 중에는 손으로 영상을 조작하기 불편합니다.
- 원하는 구절을 정확한 위치에서 시작하려면 여러 번 다시 시도하게 됩니다.

**목표**

1. 말로 정지하고 말로 재생하는 핸즈프리 구간 반복을 구현합니다.
2. 직전 구절을 말하면 그 다음 구절 위치로 이동해 재생하는 기능을 구현합니다.
3. 음원과 가사를 앱이 가져오거나 배포하지 않아, 저작권·약관 부담 없이 포트폴리오로 공개합니다.
4. 음성 명령의 반응 지연 시간을 직접 측정해 결과를 기록합니다.

## 핵심 기능

구간 마킹, 음성 정지·시작 명령, 구절 인식 점프, 연습 리포트를 네 축으로 하고, 앞의 두 축만으로도 시연 가능한 결과물이 나오도록 단계를 나눕니다.

| 기능 | 동작 | 단계 |
| --- | --- | --- |
| 영상 불러오기 | YouTube 링크를 입력하면 공식 임베드 플레이어로 영상을 띄웁니다 | 1 |
| 구간 수동 마킹 | 재생 중 버튼으로 시작과 끝을 각각 마킹해 구간으로 저장합니다. 시작만 찍는 "여기부터"도 지원합니다 | 1 |
| 정지 명령 | "잠깐, 잠깐", "스탑, 스탑"을 인식하면 재생을 멈춥니다. 명령어 외의 말이 짧은 발화만 실행합니다 | 2 |
| 정지 즉시 실행 옵션 | 정지 명령을 최종 결과를 기다리지 않고 중간 결과로 즉시 실행하는 옵션입니다. 기본값은 구현 후 측정해 정합니다 | 2 |
| 시작 명령 | "시작", "재생해", "틀어줘", "음악큐"를 인식하면 마킹한 위치부터 재생합니다. 재생 중이 아닐 때만 받고, 정지 명령과 같은 짧은 발화 규칙을 씁니다 | 2 |
| 프리롤 | 마킹 위치보다 1\~2초 앞에서 시작해 노래에 자연스럽게 들어갈 수 있게 합니다 | 2 |
| 구간 끝 동작 | 구간 끝에 도달했을 때의 동작을 고릅니다. 기본값은 자동 정지이고, 옵션으로 자동 반복과 계속 재생을 선택할 수 있습니다 | 2 |
| 명령어 설정 | 정지·시작 명령어 목록을 사용자가 수정할 수 있게 합니다. 기본 목록은 줄이지 않고 유지합니다 | 2 |
| 가사·시간 매핑 | 사용자가 구절·절과 시작 시간을 직접 입력하거나 재생하며 마킹합니다. 마지막 구절을 말했을 때 이동할 "마지막 구절 다음 위치"도 따로 입력할 수 있습니다 | 3 |
| 매핑 내보내기·불러오기 | 매핑을 JSON으로 저장하고 다시 불러옵니다. 사용자 기기에만 저장합니다 | 3 |
| 구절 인식 점프 | 직전 구절을 말하면 그 다음 구절의 시작 시간으로 이동해 재생합니다. 재생 중이 아닐 때만 받으며, 유사도 기준 기본값은 0.5입니다 | 4 |
| 연습 기록 | 구간을 재생한 시간이 최소 재생 시간 이상이면 연습 1회로 기록합니다. 기본값은 3초이고 옵션에서 바꿀 수 있습니다 | 5 |
| 연습 리포트 | 구간별 연습 횟수, 총 연습 시간, 날짜별 추이를 보여 줍니다. 기록은 브라우저 저장소에 쌓고 JSON으로 내보낼 수 있습니다 | 5 |

**구절 인식 점프의 동작 방식**

인식된 텍스트를 입력된 구절들과 유사도로 비교해 가장 가까운 구절을 찾고, 그 다음 구절의 시작 시간으로 이동합니다. 유사도 기준은 설정할 수 있고 기본값은 0.5입니다. 기준 미만이면 이동하지 않고 다시 말하도록 안내합니다. 마지막 구절은 다음 구절이 없어서, "마지막 구절 다음 위치"를 따로 입력한 경우에만 그 위치로 이동합니다. 입력이 없으면 이동하지 않고 안내만 합니다. 구절은 노래로 부르기보다 말하듯 읽는 것을 기본으로 합니다.

**구간과 연습 1회의 정의**

- **구간**: 기본은 가사 매핑의 구절·절 단위입니다. 매핑이 없거나 정확하지 않을 때는 사용자가 시작과 끝을 직접 마킹한 구간을 씁니다.
- **연습 1회**: 재생을 시작한 뒤 최소 재생 시간 이상 재생되면 1회로 셉니다. 기본값은 3초이며 옵션에서 바꿀 수 있고, 그보다 짧게 멈추면 세지 않습니다.
- **구간 끝 동작**: 구간 끝에 도달했을 때 기본값은 자동 정지입니다. 옵션으로 자동 반복(구간 시작으로 돌아가 정지 명령 전까지 반복)과 계속 재생(구간을 무시하고 이어서 재생)을 선택할 수 있습니다.

**명령 인식 규칙**

- **짧은 발화만 실행**: 명령어를 뺀 나머지 글자가 일정 수 이하일 때만 명령으로 처리합니다. 초기값은 2자이며 개발 중 조정합니다. 가사 문장에 명령어가 섞여 들어와도 실행되지 않게 하기 위해서입니다.
- **재생 상태별 허용**: 재생 중에는 정지 명령만, 재생 중이 아닐 때는 시작 명령과 구절 점프만 받습니다.
- **정지 즉시 실행(옵션)**: 최종 인식 결과가 첫 중간 결과보다 약 0.85\~1.3초 늦어, 정지만 중간 결과로 실행하는 옵션을 둡니다.

## 저작권·약관 대응 설계

앱은 음원과 가사를 가져오거나 저장하지 않고 YouTube 공식 임베드 플레이어만 제어하며, 음성 인식 대상은 사용자 본인의 목소리뿐입니다.

| 구분 | 내용 |
| --- | --- |
| 채택 | YouTube IFrame Player API만 사용해 재생·이동·정지를 제어합니다 |
| 채택 | 가사와 시간 매핑은 사용자가 직접 입력하고 본인 기기에만 저장합니다 |
| 채택 | 시연 영상과 GIF는 공유저작물, CC 라이선스 곡, 직접 녹음한 곡으로 만듭니다 |
| 채택 | README에 "영상과 가사는 사용자가 직접 입력하며 앱은 음원·가사를 포함하지 않는다"고 명시합니다 |
| 피함 | yt-dlp 같은 도구로 영상이나 오디오를 추출하는 방식 |
| 피함 | 비공식 자막 추출 라이브러리로 가사를 가져오는 방식 |
| 피함 | 가사 파일(LRC 등)을 저장소에 올리는 것 |
| 피함 | 상업 음원으로 만든 시연 영상 |

**배포 전 확인할 것**

이 내용은 법률 자문이 아니라 일반적인 설계 판단입니다. 서비스로 배포하기 전에는 YouTube API 서비스 약관 원문을 확인합니다. 코드만 GitHub에 공개하는 단계에서는 위 "피함" 항목이 저장소에 없는지만 점검하면 됩니다.

백엔드 없이 웹 앱 하나가 음성을 명령으로 바꾸고, 그 명령으로 YouTube 공식 플레이어만 제어합니다.

마이크 입력이 판별기를 거쳐 재생 컨트롤러로 전달되고, 컨트롤러가 플레이어를 제어하며 마킹과 매핑은 로컬 저장소에서 읽고 씁니다.

| 영역 | 선택 | 비고 |
| --- | --- | --- |
| 화면 | React + TypeScript | 기능이 작아 순수 JavaScript도 가능합니다 |
| 영상 재생·제어 | YouTube IFrame Player API | 다운로드 없이 공식 플레이어만 사용합니다 |
| 음성 인식 | Web Speech API | 프로토타입용이며 이후 온디바이스 방식 교체를 검토합니다 |
| 구절 매칭 | 문자열 유사도(편집 거리 기반) | 기준(기본 0.5) 미만이면 이동하지 않습니다 |
| 저장 | 브라우저 저장소 + JSON 내보내기 | 서버 없이 가사 매핑과 연습 기록을 브라우저에 저장합니다 |
| 배포 | 정적 호스팅(예: GitHub Pages) | 마이크 사용에는 HTTPS가 필요합니다 |

## PoC 검증 결과

우선순위 높은 항목은 이어폰 환경에서 통과했고, 반응 지연 수치와 어려운 구절 인식은 보완이 필요합니다.

환경은 Windows, Chrome 155, 블루투스 이어폰 마이크(Galaxy Buds Pro)이며, 2026-10-21 PoC 로그(직접 측정) 기준으로 최종 인식 34회, 명령 실행 23회, 세션 재시작과 오류는 0회였습니다.

| 항목 | 결과 | 근거와 비고 |
| --- | --- | --- |
| 자동재생 | 통과 | 음성 시작 6회와 구절 점프 6회 모두 재생됐고 반응은 264\~389ms였습니다 |
| 정지 명령 | 통과 | 로그의 11회 모두 실행됐고 정지 반응은 3\~6ms였습니다. "stop", "스톱", "멈춰"로 인식됩니다. 실패 횟수는 로그에 남지 않았습니다 |
| 오작동 | 통과(단서) | 가사에 "시작"이 섞인 문장 2건이 재생 중이라 무시됐습니다. 재생 중이 아닐 때와 가사 속 정지 단어는 막지 못해 짧은 발화 규칙을 추가했습니다 |
| 반응 지연 | 체감 통과, 수치 보완 | 발화 시작 기준 수치는 이벤트가 한 번만 들어와 무효입니다. 최종 결과는 첫 중간 결과보다 약 0.85\~1.3초 늦었습니다 |
| 구절 인식 | 일부 통과 | 정확히 인식된 구절은 4/4(유사도 0.85\~1.00)였고, 어려운 구절은 4/9(기준 0.6), 기준 0.5에서는 9/9였습니다 |

개발 후 점검할 항목은 장시간 안정성, 영상 호환성, 이동 정확도입니다. 스피커 환경은 이어폰 전제로 범위에서 제외했습니다. "잠깐", "정지", "재생해", "틀어줘"는 로그에 없어 개발 중 확인합니다.

## 기술적 과제와 해결 방안

가장 까다로운 부분은 노래 연습 환경에서 음성 인식이 흔들린다는 점이고, 대부분 임계값과 상태 구분으로 줄일 수 있습니다.

| 과제 | 원인 | 해결 방안 |
| --- | --- | --- |
| 구절 오인식 | 노래로 부르면 음성 인식 정확도가 떨어집니다 | 말하듯 읽기를 기본으로 하고, 유사도 기준을 설정할 수 있게 하며(기본 0.5), 후보 구절을 확인한 뒤 이동하는 방식을 검토합니다. 자모 단위 유사도는 최적화가 필요할 때 검토합니다 |
| 반복되는 가사 | 후렴처럼 같은 구절이 여러 번 나옵니다 | 마지막 재생 위치에 가까운 구절을 우선하거나, 절·후렴 구간을 먼저 선택하게 합니다 |
| 명령어 오작동 | 일상 대화의 "재생해", "틀어줘"가 우연히 인식됩니다 | 상태별로 받는 명령을 제한하고, 명령어 외의 말이 짧은 발화만 실행하며, 음성 인식을 켜고 끄는 버튼을 둡니다 |
| 에코 | 스피커 소리가 마이크로 들어가 "정지" 인식을 방해합니다 | 이어폰 사용을 전제로 합니다. Web Speech API에는 echoCancellation 옵션을 직접 줄 수 없을 수 있어 이 옵션에 기대지 않습니다 |
| 반응 지연 | 음성 인식 처리와 영상 버퍼링이 겹칩니다 | PoC에서 재생 반응 264\~389ms, 정지 반응 3\~6ms를 확인했습니다. 최종 인식 결과가 늦어 정지는 중간 결과로 즉시 실행하는 옵션을 검토하고, 측정 결과를 README에 기록합니다 |
| 개인정보 | 브라우저 Web Speech API는 음성을 서버로 보내 처리하는 경우가 많습니다 | 안내 문구를 넣고, 이후 온디바이스 방식(Whisper 계열, Vosk 등)으로 교체하는 것을 검토합니다 |

**상태별 허용 명령**

| 상태 | 받는 명령 | 동작 |
| --- | --- | --- |
| 대기 | 시작 명령, 구절 인식 | 마킹 위치 또는 인식된 구절의 다음 위치부터 재생 |
| 재생 중 | 정지 명령 | 재생을 멈추고 정지 상태로 이동 |
| 정지 | 시작 명령, 구절 인식 | 마킹 위치 또는 인식된 구절의 다음 위치부터 재생 |

구간 끝에 도달하면 자동 정지 설정에서는 재생 중에서 정지 상태로 이동하고, 자동 반복 설정에서는 구간 시작으로 돌아가 재생 중 상태를 유지합니다.

## 포트폴리오 어필 포인트

이 프로젝트의 강점은 기능 자체보다 약관과 저작권을 검토해 설계를 바꾼 판단 과정과, 불확실한 음성 인식 결과를 다루는 방식입니다.

- **약관 검토에 기반한 설계**: 영상 추출 방식 대신 공식 임베드 API를 선택한 이유를 설명할 수 있습니다.
- **상태 기반 음성 명령 설계**: 상태에 따라 받는 명령을 달리해 오작동을 줄인 구조를 보여 줄 수 있습니다.
- **불확실한 입력 처리**: 유사도 임계값과 후보 확인으로 오인식에 대응한 과정을 설명할 수 있습니다.
- **측정과 개선**: 반응 지연 시간을 측정하고 개선한 기록을 남깁니다.

## 리스크 및 향후 확장 아이디어

가장 큰 리스크는 약관 변경과 브라우저 환경 차이이며, 둘 다 프로토타입 단계에서 먼저 확인할 수 있습니다.

**리스크**

- **약관 변경**: YouTube API 서비스 약관은 바뀔 수 있으므로 공개·배포 전에 다시 확인합니다.
- **임베드가 막힌 영상**: 영상 소유자가 임베드를 허용하지 않으면 재생할 수 없으므로 오류 안내가 필요합니다.
- **브라우저 지원 차이**: Web Speech API는 브라우저마다 지원 범위가 달라, 지원 브라우저를 README에 명시합니다.
- **자동재생 정책**: PoC(Chrome)에서는 마이크를 켠 뒤 음성 명령으로 재생이 12/12회 시작됐습니다. 다른 브라우저는 확인하지 않았습니다.

**향후 확장 아이디어**

- 온디바이스 음성 인식(Whisper 계열, Vosk 등)으로 교체해 프라이버시와 오프라인 사용을 개선
- 재생 속도 조절로 어려운 구간을 천천히 연습
- 사용자가 자기 기기의 음원 파일을 직접 불러오는 모드
